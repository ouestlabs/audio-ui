## Usage

An arrangement plays as blocks of frames on the audio thread. This module holds the arithmetic of that: which frame of the arrangement plays at a frame of the audio clock, which clips sound in a block and where each reads its recording, and how the mixer lines its paths up. The registry's [`clip-player`](/docs/lib/clip-player) runs it in an `AudioWorklet`, and the [`arrangement-engine`](/docs/lib/arrangement-engine) and [`mixer-engine`](/docs/lib/mixer-engine) build on it.

## The clip player

`CLIP_PLAYER_WORKLET` is the player's processor as the source of a module. Load it once into a context, then make a player per track:

```ts
import { CLIP_PLAYER_PROCESSOR, CLIP_PLAYER_WORKLET, playedClips } from "@audio-ui/core/playback";

const url = URL.createObjectURL(new Blob([CLIP_PLAYER_WORKLET], { type: "text/javascript" }));
await ctx.audioWorklet.addModule(url);

const player = new AudioWorkletNode(ctx, CLIP_PLAYER_PROCESSOR, {
  numberOfInputs: 0,
  numberOfOutputs: 1,
  outputChannelCount: [2],
});
player.connect(ctx.destination);

player.port.postMessage({ type: "recording", id: "take-1", channels, sampleRate: buffer.sampleRate });
player.port.postMessage({ type: "clips", clips: playedClips(track.clips, (clip) => clip.recordingId, ctx.sampleRate) });
player.port.postMessage({ type: "state", state: { at: 0, loop: null, playing: true, position: 0 } });
```

A recording posted through one player is there for every player of the context. `playedClips` turns an arrangement's clips into what the player reads, in whole frames: the clips that play, each with its place, its fades, its gain, its loop and its warp or stretch. The messages a player takes are `ClipPlayerMessage`: a decoded or a streamed recording, `forget`, the clips, a state of the transport, `sync` (answered once every message before it is in) and `dispose`.

## The transport

A `PlaybackState` says what plays from a frame of the audio clock on: whether it plays, the frame of the arrangement at that frame, and the loop. `STOPPED` is the state at rest. `playbackRuns(state, frame, count)` cuts a block into runs of consecutive frames of the arrangement, cut where the loop comes round; `arrangementFrame` is the one frame, `rescaled` carries a state through a change of tempo, and `heardFrame` turns the context's time of what is heard now (`getOutputTimestamp().contextTime`) into a frame of the audio clock, for a playhead that matches the speakers.

`TrackRenderer` is what one track plays, block after block. A state that arrives late takes over at once and still plays the frames its clock says, and a stop or a jump fades out over `DECLICK_SECONDS` (2 ms), so it does not click.

## Streamed recordings

A recording too long to hold decoded is read from pages in shared memory. `createPagePool(slots)` makes the pool every streamed recording of a context reads from, `createRecordingStream` a recording in it, and `RECORDING_LOADER_WORKER` is the worker that loads pages into it from a file in the origin private file system. `pagesAhead` lists the pages the next frames will read, soonest first, and `PageCache` keeps them in the pool. A page that is not there yet plays as silence.

## The mixer

```ts
import { delayCompensation, panGains, soloState } from "@audio-ui/core/playback";

panGains(0); // [1, 1]: both channels at unity in the centre
panGains(-1); // [1.414, 0]: the side it is turned to at +3 dB

const solo = soloState([
  { id: "drums", kind: "track", soloed: true },
  { id: "bass", kind: "track", soloed: false },
  { id: "verb", kind: "return", soloed: false },
]);
solo.heard("bass"); // false
solo.sends("drums", "verb"); // true: a soloed track's sends still reach its return

const { tracks, total } = delayCompensation(
  [{ id: "drums", latency: 128 }, { id: "bass", latency: 0 }],
  []
);
// bass waits 128 frames after its chain, so both reach the main track together
```

`soloState` takes groups too: a group is heard while a track in it is soloed. `routedCompensation` lines paths up wherever they meet, at a group, a return or the main track, for a mixer that routes tracks into groups.
