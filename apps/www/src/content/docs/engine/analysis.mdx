## Usage

The functions take samples, bins or settings and return numbers, with no Web Audio node in them, so they run wherever the data is.

## Levels

```ts
import { dbToGain, gainToDb, peakDb, rmsDb } from "@audio-ui/engine/analysis";

rmsDb(samples); // how loud they sound: -3 dB for a sine at full scale
peakDb(samples); // how near they come to clipping: 0 dB for the same sine
dbToGain(-6.02); // 0.5
```

<ForFrameworks only="react">

The registry's [`useAudioLevels`](/docs/hooks/use-audio-levels) reads an analyser through them into what a [Meter](/docs/components/base/meter) draws.

</ForFrameworks>

## Spectrum

`logSpectrum(bins, sampleRate, out, { minHz, maxHz })` resamples an analyser's bins (`getFloatFrequencyData`) onto a log frequency axis, written into `out`, as many points as it holds. `holdPeaks(spectrum, peaks, holding, elapsed, { hold, fall })` keeps each point's loudest level for `hold` seconds, then lets it fall at `fall` dB a second, one frame at a time. `spectrumBands` reduces a spectrum to a few levels from 0 to 1, for bars. [`useSpectrum`](/docs/hooks/use-spectrum) runs them on every frame.

## Curves

A filter, an equalizer and a compressor each have a curve a panel draws. Each function returns the curve as a function, to be sampled at as many points as the plot has:

```ts
import { biquadResponse, compressorOutput, eqResponse } from "@audio-ui/engine/analysis";

const cut = biquadResponse({ type: "highcut", frequency: 1000 });
cut(1000); // -3.01 dB at the cutoff

const eq = eqResponse([
  { type: "peak", frequency: 1000, gainDb: 6, q: 1 },
  { type: "highshelf", frequency: 8000, gainDb: -3 },
]);
eq(1000); // 6 dB: the bands add up at each frequency

const compressor = compressorOutput({ thresholdDb: -20, ratio: 4 });
compressor(-8); // -17: 12 dB over the threshold comes out 3 dB over
```

The band types are the ones an equalizer shows (`lowcut`, `highcut`, `lowshelf`, `highshelf`, `peak`, `notch`, `bandpass`). `WEB_AUDIO_FILTER_TYPES` maps each to the `BiquadFilterNode` type that sounds as drawn, and `toWebAudioQ` converts a band's Q for the node. `bandHandleDb` and `bandGainForHandle` place a band's handle on the summed curve and back, so a dragged handle stays under the pointer.

## Waveforms

`computePeaks(channels, buckets)` reduces a recording to the lowest and highest sample of each slice, across its channels, which is what a waveform draws; `normalizePeaks` scales them to full height.

## Tempo and transients

`detectTransients(channels, sampleRate)` finds where a recording's level rises sharply, in seconds. `detectSilences(channels, sampleRate)` finds where it pauses between its sounds, as `[from, to]` in seconds: each stretch of at least 60 ms where every sample stays under -34 dBFS, or 20 dB under the loudest sample of a quiet recording (`threshold` in dBFS and `minDuration` in seconds set your own). Between them, an editor selects a sound as a text selects a word: from one transient to the next, or from one pause to the next. `autoWarp` works out how a recording plays in time at an arrangement's tempo, from a tempo estimate and those transients: a short recording that 1, 2, 4, 8 or 16 bars fit at its tempo is taken as that loop, marked at its start and end; any other gets a warp marker on the first beat of each bar, moved onto a transient within an eighth of a beat. It returns the tempo, the offset of the first beat and the markers, or `null` when there is no tempo to go by.

## Loudness

`loudness` measures a whole sound the way streaming services and broadcasters do (ITU-R BS.1770): its integrated loudness in LUFS, its loudest sample, and its true peak, the loudest point of the waveform between the samples. `loudnessGain` is the gain that brings it to a target as far as its true peak stays under a ceiling, -1 dBTP unless told otherwise: a sound that would pass it lands under the target instead, and nothing is limited.

```ts
import { dbToGain } from "@audio-ui/engine/analysis";
import { LOUDNESS_TARGETS, loudnessGain, measureLoudness } from "@audio-ui/engine/analysis";

const loudness = measureLoudness(channels, sampleRate); // { lufs: -19.2, peak: -3.1, truePeak: -2.8 }
const gain = dbToGain(loudnessGain(loudness, LOUDNESS_TARGETS.streaming));
const normalized = channels.map((channel) => channel.map((sample) => sample * gain));
```

It reads every sample, the true peak at four points a sample: about half a second a minute of loud stereo on a laptop, so measure where the page can wait, as an export does. `LOUDNESS_TARGETS` holds -14 LUFS for streaming, -16 for podcasts and -23 for broadcast (EBU R 128).

## Pitch

`detectPitch(samples, sampleRate, { minHz, maxHz, minLevel, threshold })` is the pitch a stretch of samples holds: the YIN algorithm of `@audio/pitch-yin`, between `minHz` and `maxHz`, which a stretch must hold two periods of the lowest of. It returns `{ frequency, confidence }`, or `null` for a signal quieter than `minLevel`, an RMS level from 0 to 1, or with no clear period, such as noise or a chord. A tuner reads it a few dozen times a second and keeps the median of the last few readings; [`usePitch`](/docs/hooks/use-pitch) does that for a React page.

## A recording as it comes in

Two readings are taken once, as a recording is decoded:

- `analyzeBeat(channels, sampleRate)` reads its tempo with `@audio/beat-detect` and fits the beat grid on its transients, to the sample, so a tempo between whole BPM holds over a long file. It returns `{ estimate, transients }`, the estimate `null` for a sound with no attack (silence, noise), which is what `autoWarp` takes.
- `audioChroma(channels, sampleRate)` is how much of its sound lies in each pitch class, C to B, summing to 1: the chroma of `@audio/mir-chroma` on each stretch that is not silence, averaged. It is what a key is read from, with [`detectKeys`](/docs/engine/pitch#keys).

## Reading a sound

```ts
import { checkAcx, reportSound } from "@audio-ui/engine/analysis";

const report = reportSound(channels, sampleRate);
report.loudness.lufs; // -19.5
report.key; // { name: "minor", root: 9 }, or null
report.tempo; // 128, or null for a sound with no beat
report.acx.pass; // RMS -23 to -18 dBFS, peak at most -3 dBFS, noise floor at most -60 dBFS

checkAcx(channels, sampleRate).noiseFloor.value; // the quietest pause of half a second, in dBFS RMS, or null
```

`reportSound` reads every sample, a few seconds a minute of stereo on a laptop, so call it where the page can wait.

## Colouring a waveform

```ts
import { bandShares } from "@audio-ui/engine/analysis";

const { low, mid, high } = bandShares(channels, sampleRate, 8192);
low[slice]; // 0 to 1: the share of the slice under 250 Hz, the loudest of the three bands being 1
```

`bandShares` cuts a sound into `count` slices and tells, for each, how its energy is spread over the lows (under 250 Hz), the mids and the highs (over 2.5 kHz). Give the three arrays to `ClipWaveform`'s `tint`, with `mode: "temperature"` (warm where the lows lead, cool where the highs do) or `"bands"` (lows red, mids green, highs blue).
