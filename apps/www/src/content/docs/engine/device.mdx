## Usage

`defineDevice` describes an effect or an instrument by its parameters, with no sound and no view in it. What comes back holds everything that reads or changes a state of it:

```ts
import { defineDevice } from "@audio-ui/engine/device";

export const driveDevice = defineDevice({
  id: "drive",
  name: "Drive",
  description: "Soft clipping with a tone control.",
  parameters: [
    { id: "amount", label: "Amount", min: 0, max: 100, default: 25, unit: "%" },
    { id: "tone", label: "Tone", min: 200, max: 20000, default: 4000, scale: "log", unit: "Hz" },
    { id: "bypass", label: "Bypass", kind: "toggle", default: false },
  ],
});

const state = driveDevice.defaults(); // { amount: 25, tone: 4000, bypass: false }
```

A parameter is a number in a range (on a scale, in steps, with a unit), a `"toggle"`, or a `"choice"` from a list of options. A definition that cannot work, such as a default out of its range, a log scale that starts at 0 or a choice whose default is not one of its options, throws `DeviceDefinitionError` when the module loads, not when a user turns a knob.

## Changing a state

A state is a plain object, so it is stored, sent and undone like any other. `set(state, id, value)` changes one parameter, clamped and snapped; `apply(state, changes)` changes several and says what happened to each:

```ts
const { state: next, changes, rejected } = driveDevice.apply(state, {
  amount: 140,
  tone: "bright",
  gain: 3,
});
// changes:  [{ id: "amount", from: 25, to: 100, adjusted: true }]
// rejected: [{ id: "tone", reason: "not a number" }, { id: "gain", reason: "unknown parameter" }]
```

A value out of range is brought in and marked `adjusted`; a value of the wrong type, or an id the device does not have, is rejected and the parameter is left as it was. `sanitize` makes a valid state of anything, such as a preset saved by an older version. `normalize` and `denormalize` place a value along its travel from 0 to 1, on its scale, which is what a knob draws, and `format` prints it with its unit, "4000 Hz".

## Bindings

A device makes no sound. An engine does, and it implements a binding: `update(state, context)` whenever the state changes, `dispose()` when it goes, and `readings()` for a meter, such as the gain reduction of a compressor. An `InstrumentBinding` also takes `noteOn` and `noteOff`, and a `SidechainBinding` has a second input for a key signal. `playNote(instrument, note, seconds)` plays a note on one and lets it go when the time is up.

`latency(state, sampleRate)` is how long the device delays the sound, for a host to compensate; `describe()` is the device as JSON, what a catalog lists.

## Tools for an agent

`deviceTools(device)` derives the tools a model calls to drive it: `<id>_set` takes any parameters by id, `<id>_reset` puts some or all back, and an instrument played by notes also gets `<id>_play`. Each has a JSON Schema input and a `run(state, input)` that never throws on a model's input:

```ts
import { deviceTools } from "@audio-ui/engine/device";

const [set] = deviceTools(driveDevice);
set.run(state, { amount: 60 });
// { state: { amount: 60, tone: 4000, bypass: false }, summary: "Amount: 25 % to 60 %" }
```

The schema is the subset that OpenAI, Anthropic, MCP and the AI SDK all accept, and the ranges it gives are the ones the device enforces.
