**audio/ui** is a toolkit for building audio interfaces on the web: headless primitives on npm, for React (`@audio-ui/react`) and as custom elements for any framework (`@audio-ui/elements`), and styled components for [shadcn/ui](https://ui.shadcn.com/) that you copy, paste and customize.

## Current Status

Available today:

### Packages

- **[`@audio-ui/core`](/docs/core)**: the logic of every control, with no dependency
- **[`@audio-ui/engine`](/docs/engine)**: the audio logic (devices, time, analysis, MIDI, scales, playback, files), on audio.js
- **[`@audio-ui/react`](/docs/react)**: the headless React primitives
- **[`@audio-ui/elements`](/docs/elements)**: every primitive as custom elements, for plain HTML and any framework, with template types for [Vue](/docs/elements/vue) and [Svelte](/docs/elements/svelte)
- **[`@audio-ui/icons`](/docs/icons)**: audio glyphs, one thin stroke on a 24 grid

### Elements

The pieces of any audio interface:

- **Controls**: Knob, Fader, XY Pad and Envelope, with scales, rulers and fine drag
- **Keyboards and pads**: Piano and Pad
- **Displays**: Meter and Needle meter (a VU dial to the standard), Waveform, from peaks, a live signal or a range of the audio, Plot, for curves and draggable points, Spectrum analyzer and Tuner

### Workstation

The surfaces of a DAW, controlled and independent of any audio engine:

- **Arrangement**: Timeline, a zoomable ruler with lanes, ranges and a navigator, and the arrangement editor on top of it: tracks of clips, selection, time commands, mixes, tempo, signatures, locators, loop and undo
- **Editors**: Piano Roll, with scales, edits, lanes and a MIDI file in and out, and Sequencer
- **Piano roll tools**: Scale menu, Note find and Note edit menu
- **Transport**: Transport and Scrubber
- **Mixing**: Mixer, and the device chain: a track's devices in a row, each drawn by its own panel, with a library to add one from

### Devices

47 effects and instruments, each a definition, a Web Audio engine and a panel generated from its parameters: dynamics, tone, distortion, space and modulation, and utility, and eleven instruments, synths, keys, a sampler, a drum synth and a guitar. A device reports what it takes off the signal for a meter, and exposes tools for an agent. See [Devices](/docs/devices).

### Audio engine

The hooks and libraries on the Web Audio API that make the sound, for the components that need it, over `@audio-ui/engine`: output, clock and time, synthesis, input and analysis. An engine of your own can drive the same components. See [Guides](/docs/guides).

### Blocks

Pre-assembled patterns: a mixing console, a drum rack, a piano roll, a timeline, a waveform player, and a block for each device. Browse the [component catalog](/components).

### For agents

- **[MCP server](/docs/mcp)**: list components, read their docs and search the catalog from your agent
- **[Agent skill](/docs/agents)**: teaches your agent which layer to pick and how to wire each component

## What's Next

- **Native Vue and Svelte packages**: the [custom elements](/docs/elements) work in any framework, with template types and binding for [Vue](/docs/elements/vue) and [Svelte](/docs/elements/svelte). A package per framework stays thin only once each part's attributes and handlers come from `@audio-ui/core`, as its logic already does, so that comes first.
- **Agents**: the Agent Skill and the MCP server have a link on the home page and a page each. They should be easier to find, from the documentation overview and from the component pages, with what an agent gets from each in a few lines.
- **Devices**: a device is a definition, an engine and a panel, and the panel is generated from the parameters alone, with no code of its own per device. That is shown on the Devices page as one device in two skins; it should be shown as the idea it is, with the contract (the parameters, the readings, the tools for an agent) in plain view.
- **More audio components**: further audio-specific patterns and controls.
