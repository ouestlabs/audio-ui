`@audio-ui/elements` holds the knob and the fader of audio/ui as custom elements, for a page in Vue, in Svelte, or with no framework at all. They are the same parts as the [primitives](/docs/primitives) of `@audio-ui/react`, built on the same `@audio-ui/core`: the same keys, drag and wheel, the same native `<input type="range">` in each thumb, the same `data-*` attributes to style from. The two below take the classes of the registry's own Knob and Fader.

<ElementsPreview />

## Installation

```bash
npm install @audio-ui/elements
```

Importing a subpath registers its elements. Import it once, where the page starts:

```js
import "@audio-ui/elements/knob";
import "@audio-ui/elements/fader";
```

`@audio-ui/elements` alone registers both. On a server, the import does nothing, and the elements come to life in the browser.

The fader takes the same shape: `<audio-ui-fader>`, with `-label`, `-control`, `-track`, `-indicator`, `-thumb` and `-value` parts.

## Value and events

- **`input`** fires on every change: a drag, a key, the wheel, a reset. `event.detail.value` is the new value and `event.detail.reason` what changed it (`"drag"`, `"keyboard"`, `"wheel"`, `"reset"`, `"input-change"`, and `"track-press"` on a fader). `preventDefault()` refuses it, and the control stays where it was.
- **`change`** fires once, when a gesture that changed the value ends: the time to start a note, push to an undo stack or save.
- **`value`**, the property, reads the value and moves the control when you set it. A framework that binds it (`:value` in Vue, `value={}` in Svelte) sets it. While a pointer drags, the control follows the pointer even if the value you set lags behind.
- **`name`** makes the thumb's input a field of the form around it, submitted with the value.

## Styling

The elements set only what they need to work: `display: block` on the parts that are boxes, `position: relative` and `touch-action: none` on the control, the thumb's rotation or place, in rules with no specificity, so any rule of yours wins. No color, size or spacing comes from them. Style them from the same attributes as the React parts:

```css
audio-ui-knob-control { width: 4rem; height: 4rem; cursor: grab; }
audio-ui-knob[data-dragging] audio-ui-knob-control { cursor: grabbing; }
audio-ui-knob-track, audio-ui-knob-indicator { position: absolute; inset: 0; }
audio-ui-knob-track { color: var(--muted); }
audio-ui-knob-indicator { color: var(--primary); }
audio-ui-knob-thumb:has(input:focus-visible) { outline: 2px solid var(--ring); }
```

The track and the indicator draw their arc with `currentColor`. A class works too: the preview above uses the classes of the registry's Knob and Fader, as Tailwind writes them.

### Pad

`<audio-ui-pad>` is a grid of pads to strike, a group: each pad sounds while held, by pointer or with Enter or Space, and each pointer holds its own pad. A strike is harder where a pen or screen presses harder, or else toward the top of the pad. The pads are one tab stop: the arrows walk them, up and down by a row.

<TypeTable>
<TypeRow name={"columns"} type={"number"} default={"4"}>How many pads a row holds: what the up and down arrows move by. Lay the grid out to match.</TypeRow>
<TypeRow name={"active-pads"} type={"string"}>Pads lit from elsewhere, such as a sequencer or a MIDI input, separated by spaces. The `activePads` property takes an array.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

A strike fires `padon`, with `event.detail` `{ value, velocity, reason }`: `preventDefault()` keeps it silent. A release fires `padoff`, with `{ value, reason }`, and `reason` is `"choke"` when another pad of its group stopped it.

| Part | What it is |
| --- | --- |
| `<audio-ui-pad-item>` | One pad, a button named by its content. `value` names it in the events; pads sharing a `choke-group` stop each other; `disabled` silences one. How hard it was last struck is its `--pad-velocity` CSS variable, from 0 to 1 |

### Piano

`<audio-ui-piano>` is a keyboard to play, a group: every key sounds while pressed, by pointer or with Enter or Space. Dragging across the keys glides from one to the next, and each pointer holds its own key, so chords can be played on a touch screen. The keys are one tab stop: the arrows walk them, Shift by an octave.

<TypeTable>
<TypeRow name={"min-pitch"} type={"number"} default={"48"}>Lowest MIDI pitch, inclusive: 60 is middle C.</TypeRow>
<TypeRow name={"max-pitch"} type={"number"} default={"72"}>Highest MIDI pitch, inclusive.</TypeRow>
<TypeRow name={"pitches"} type={"string"}>Only these pitches get keys, separated by spaces. The `pitches` property takes an array.</TypeRow>
<TypeRow name={"active-notes"} type={"string"}>Pitches lit from elsewhere, such as a MIDI input or a sequencer. The `activeNotes` property takes an array.</TypeRow>
<TypeRow name={"layout"} type={"\"keyboard\" | \"even\""} default={"\"keyboard\""}>How the keys share the length: like a piano, or one equal share each, as a piano roll's rows.</TypeRow>
<TypeRow name={"orientation"} type={"\"horizontal\" | \"vertical\""} default={"\"horizontal\""}>Vertical puts the low end at the bottom.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

A key that starts sounding fires `noteon`, with `event.detail` `{ pitch, velocity, reason, event }`, `event` being the pointer or key event that played it: `preventDefault()` keeps it silent. One that stops fires `noteoff`, with `{ pitch, reason, event }`.

| Part | What it is |
| --- | --- |
| `<audio-ui-piano-keys>` | Makes an `<audio-ui-piano-key>` for each pitch, lowest first, each holding what its `<template>` holds. It takes no room of its own |
| `<audio-ui-piano-key>` | One key, a button placed for its `pitch` and named after it ("C4"). `data-color` is `black` or `white` |
| `<audio-ui-piano-key-label>` | The name of the key it sits in, hidden from assistive technology |

### Sequencer

`<audio-ui-sequencer>` is a grid of steps to switch on and off, a row per sound, a group: pressing a cell flips it, and dragging on carries the new state across every cell the pointer crosses. The cells are one tab stop, walked with the arrow keys. The rows and the steps are made from templates:

```html
<audio-ui-sequencer aria-label="Pattern" default-value="x...x... ..x...x.">
  <audio-ui-sequencer-rows labels="Kick, Snare">
    <template>
      <audio-ui-sequencer-steps>
        <template><audio-ui-sequencer-cell></audio-ui-sequencer-cell></template>
      </audio-ui-sequencer-steps>
    </template>
  </audio-ui-sequencer-rows>
</audio-ui-sequencer>
```

<TypeTable>
<TypeRow name={"value"} type={"string"}>The pattern as text: a word per row, a character per step, `x` for a step on and `.` for one off. The `value` property takes and gives it as `boolean[][]`.</TypeRow>
<TypeRow name={"default-value"} type={"string"}>The starting pattern, written the same way.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

Flipping cells fires `input`, with `{ value, reason }`, which `preventDefault()` refuses, then `change`. The `velocities` property (`number[][]`, 0 to 1) holds how loud each step plays; drawing them fires `velocityinput` and `velocitychange`, with `{ velocities, reason }`. The `source` property, `{ getSnapshot, subscribe }` giving the step being played, marks that step's cells with `data-current` as the clock ticks.

| Part | What it is |
| --- | --- |
| `<audio-ui-sequencer-rows>` | Makes an `<audio-ui-sequencer-row>` per row of the pattern from its `<template>`; `labels` names them, separated by commas |
| `<audio-ui-sequencer-row>` | One sound's row, a group, for its `index` |
| `<audio-ui-sequencer-steps>` | Makes an `<audio-ui-sequencer-step>` per step of its row from its `<template>`. Neither takes room, so the cells are the grid's own items |
| `<audio-ui-sequencer-cell>` | One step, a toggle button pressed when it is on (`data-on`), named after its row and step ("Kick, step 5") |
| `<audio-ui-sequencer-velocity>` | How loud a step plays, as a bar whose height is the `--sequencer-velocity` CSS variable; a press or a drag sets it, Alt + click or Delete bring it back to full, and a native range input takes the keys |

### Envelope

`<audio-ui-envelope>` is a breakpoint envelope, a group: drag a point to move it, double click the graph to add one, and double click, Alt + click or Delete to remove one. The points are one tab stop: Page Up and Page Down (or Home and End) move between them, and the arrow keys move the focused one. Each segment has a handle on its midpoint that bends it, and Alt + drag on the graph bends the segment under the pointer. The points and segments elements make a handle each, from a `<template>` if they have one:

```html
<audio-ui-envelope aria-label="Amp envelope" default-value="0 0, 0.2 1, 0.6 0.5, 1 0">
  <audio-ui-envelope-graph>
    <audio-ui-envelope-fill></audio-ui-envelope-fill>
    <audio-ui-envelope-line></audio-ui-envelope-line>
  </audio-ui-envelope-graph>
  <audio-ui-envelope-segments></audio-ui-envelope-segments>
  <audio-ui-envelope-points></audio-ui-envelope-points>
</audio-ui-envelope>
```

<TypeTable>
<TypeRow name={"value"} type={"string"}>The points, separated by commas, each `x y` or `x y curve` in 0 to 1, the curve from -1 to 1. The `value` property takes and gives them as `{ x, y, curve? }[]`.</TypeRow>
<TypeRow name={"default-value"} type={"string"}>The starting points, written the same way. Defaults to an ADSR shape.</TypeRow>
<TypeRow name={"min-points"} type={"number"} default={"2"}>Removing a point is refused at this count.</TypeRow>
<TypeRow name={"max-points"} type={"number"}>Adding a point is refused at this count.</TypeRow>
<TypeRow name={"snap"} type={"string"} default={"0"}>The grid the pointer puts points on: one step, such as `0.25`, or `"x y"` for each axis (`"0.125 0"` snaps across and leaves the level free). Cmd or Ctrl leaves it.</TypeRow>
<TypeRow name={"step"} type={"number"} default={"0.01"}>The keyboard step on both axes.</TypeRow>
<TypeRow name={"format"} type={"string"}>`Intl.NumberFormat` options as JSON, for each point's coordinates.</TypeRow>
<TypeRow name={"locale"} type={"string"}>Defaults to the browser's language.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

`input` and `change` carry `{ value, reason, index }`, the reason `drag`, `keyboard`, `add`, `remove` or `curve`. The `getPointValueText(point, index)` and `getCurveValueText(curve, index)` properties write what a screen reader hears, in real units.

| Part | What it is |
| --- | --- |
| `<audio-ui-envelope-graph>` | The drawing surface, filling the envelope: a double click adds a point, and it carries `data-blocked` briefly when adding is refused |
| `<audio-ui-envelope-line>` | The curve through the points, in `currentColor`; `stroke-width` sets its width, which the stretch leaves alone |
| `<audio-ui-envelope-fill>` | The area under the curve, in `currentColor` |
| `<audio-ui-envelope-points>` | Makes an `<audio-ui-envelope-point>` per point; `label` names them, `{n}` the number and `{count}` how many ("Point {n} of {count}" by default) |
| `<audio-ui-envelope-point>` | A slider on the point's level, placed with `left` and `bottom`. It carries `data-dragging` while dragged, `data-removable` while it can be removed, and `data-blocked` briefly when removal is refused |
| `<audio-ui-envelope-segments>` | Makes an `<audio-ui-envelope-segment>` per segment; `label` names them ("Curve {n}" by default) |
| `<audio-ui-envelope-segment>` | A slider on the curve, from -1 to 1, on the segment's midpoint: drag it or press Up and Down to bend, double click or Delete to straighten. `data-flat` marks a segment with nothing to bend |

### Plot

`<audio-ui-plot>` holds two axes and everything drawn on them, in the axes' units: an equalizer's response, a filter's cutoff, a compressor's curve. Each drawing covers the plot with an SVG of its own, in `currentColor`, its strokes the same width however the plot stretches. A curve takes its function, and a trace its live source, as properties:

```html
<audio-ui-plot min-x="20" max-x="20000" scale-x="log" min-y="-24" max-y="24">
  <audio-ui-plot-grid></audio-ui-plot-grid>
  <audio-ui-plot-line axis="y" value="0"></audio-ui-plot-line>
  <audio-ui-plot-curve></audio-ui-plot-curve>
  <audio-ui-plot-handle aria-label="Low" value="200 6"></audio-ui-plot-handle>
</audio-ui-plot>
<script type="module">
  document.querySelector("audio-ui-plot-curve").fn = (hz) => response(hz);
</script>
```

### Waveform

`<audio-ui-waveform>` shows a sound and, with a control, seeks through it: a press jumps to the pointer, a drag scrubs, and the keys step through. Its shape is its `peaks` property, known upfront, or a live `levels` signal; its position is its `value`, or a live `source`, and it is the `--waveform-position` CSS variable the playhead and thumb follow:

```html
<audio-ui-waveform duration="102">
  <audio-ui-waveform-control aria-label="Seek">
    <audio-ui-waveform-canvas></audio-ui-waveform-canvas>
    <audio-ui-waveform-playhead></audio-ui-waveform-playhead>
  </audio-ui-waveform-control>
</audio-ui-waveform>
<script type="module">
  document.querySelector("audio-ui-waveform").peaks = peaks;
</script>
```

<TypeTable>
<TypeRow name={"duration"} type={"number"} default={"1"}>Length of the audio, in the unit the position is in, typically seconds.</TypeRow>
<TypeRow name={"value"} type={"number"}>The playback position, from 0 to `duration`.</TypeRow>
<TypeRow name={"default-value"} type={"number"} default={"0"}></TypeRow>
<TypeRow name={"step"} type={"number"}>Step for the arrow keys. Defaults to a hundredth of `duration`.</TypeRow>
<TypeRow name={"large-step"} type={"number"}>Step for Page Up, Page Down and Shift + arrows. Defaults to a tenth of `duration`.</TypeRow>
<TypeRow name={"range"} type={"string"}>The stretch shown, `"start end"`: a clip's window onto its source, a zoomed view. Defaults to the whole audio; while the position is outside it, the waveform carries `data-outside`.</TypeRow>
<TypeRow name={"loading"} type={"boolean"}>The audio is still on its way: seeking waits, and the bars sweep.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

Seeking fires `input` and `change` with `{ value, reason }`. While a live signal is audible the waveform carries `data-active`.

| Part | What it is |
| --- | --- |
| `<audio-ui-waveform-control>` | The seekable surface, holding the native range input that takes focus and the keys. Its `getAriaValueText(value, duration)` property says how the position is announced. With `selectable`, a Shift + drag selects a stretch, firing `selectioninput` and `selectioncommit` with `[start, end]` |
| `<audio-ui-waveform-canvas>` | Draws the waveform on a canvas, sharp at any pixel density: `variant` (`mirror`, `bars`, `line`, or `scope` for raw samples), `bar-width`, `bar-gap`, `bar-radius`, `min-bar-height`, `gain`, `mirrored`, `idle`, `mode` (`static` or `scrolling`), `scroll-speed` and `line-width`. The played part is `--waveform-progress-color`, the rest `--waveform-color` |
| `<audio-ui-waveform-bars>` | Makes `count` `<audio-ui-waveform-bar>`s (24), each at its level in the `--waveform-level` CSS variable, for a visualizer styled in CSS; bars the position has passed carry `data-played`. Also `gain`, `idle`, `min-level` and `mirrored` |
| `<audio-ui-waveform-playhead>` | A mark at the position |
| `<audio-ui-waveform-thumb>` | A handle centered on the position |
| `<audio-ui-waveform-hover>` | Shown at the hovered point; its `format(value, duration)` property writes it as text |
| `<audio-ui-waveform-marker>` | A cue at its `value`, labelled by its content |
| `<audio-ui-waveform-region>` | A loop or a selection, from its `value` (`"start end"`): dragging its body moves it, unless `movable="false"`. It fires `regioninput` and `regionchange` with `{ value, edge, reason }`, so a seek listener never takes them |
| `<audio-ui-waveform-region-handle>` | Resizes the `edge` (`start` or `end`) of its region, by dragging or through the range input it holds |

### Timeline

`<audio-ui-timeline>` is an arrangement: a ruler that moves the position, lanes of clips to move, trim and fade, loop ranges, and a viewport that scrolls and zooms them. Units are yours: seconds, beats, steps. Each part that holds a value of its own fires events named after it, so a listener on the timeline for the position never takes them, and one listener there can serve every clip:

```html
<audio-ui-timeline duration="32" snap-step="1">
  <audio-ui-timeline-viewport>
    <audio-ui-timeline-ruler aria-label="Position"></audio-ui-timeline-ruler>
    <audio-ui-timeline-track>
      <audio-ui-timeline-track-header>Drums</audio-ui-timeline-track-header>
      <audio-ui-timeline-lane seekable>
        <audio-ui-timeline-clip aria-label="Beat" start="4" length="8">
          <audio-ui-timeline-clip-header>Beat</audio-ui-timeline-clip-header>
        </audio-ui-timeline-clip>
        <audio-ui-timeline-playhead></audio-ui-timeline-playhead>
      </audio-ui-timeline-lane>
    </audio-ui-timeline-track>
  </audio-ui-timeline-viewport>
</audio-ui-timeline>
```

<TypeTable>
<TypeRow name={"duration"} type={"number"} default={"1"}>Length of the timeline, in your units.</TypeRow>
<TypeRow name={"position"} type={"number"}>The playback position. The `source` property follows a live one instead.</TypeRow>
<TypeRow name={"default-position"} type={"number"} default={"0"}></TypeRow>
<TypeRow name={"zoom"} type={"number"}>px per unit. Leave it out and the timeline fits the width it is given.</TypeRow>
<TypeRow name={"default-zoom"} type={"number"}></TypeRow>
<TypeRow name={"min-zoom"} type={"number"} default={"0"}></TypeRow>
<TypeRow name={"max-zoom"} type={"number"}></TypeRow>
<TypeRow name={"snap-step"} type={"number"} default={"0"}>Distance between grid lines: every gesture lands on the grid unless Cmd/Ctrl is held. 0 is no grid.</TypeRow>
<TypeRow name={"snap-offset"} type={"number"} default={"0"}>Where the grid's lines start.</TypeRow>
<TypeRow name={"snap-points"} type={"string"}>Places that pull a dragged clip or range onto them from a few px away, separated by spaces: the edges of other clips, the locators.</TypeRow>
<TypeRow name={"step"} type={"number"}>Step for the arrow keys. Defaults to `snap-step`, or a hundredth of `duration`.</TypeRow>
<TypeRow name={"large-step"} type={"number"}>Step for Page Up and Page Down. Defaults to ten steps.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

Moving the position fires `input` and `change` with `{ value, reason }`; a new zoom fires `zoomchange`, which `preventDefault()` refuses. Every lane sets `--timeline-unit`, the width of one unit, and what is placed on it sets `--timeline-offset` and `--timeline-length`.

| Part | What it is |
| --- | --- |
| `<audio-ui-timeline-viewport>` | The scrolling window: Cmd/Ctrl + wheel and a pinch zoom around the pointer |
| `<audio-ui-timeline-ruler>` | The lane that moves the position, holding the native range input for the keys. With `selectable`, a Shift + drag selects a stretch, firing `selectioninput` and `selectioncommit` |
| `<audio-ui-timeline-lane>` | A strip parts are placed on. With `seekable`, a press on its bare area moves the position; with `selectable` too, a drag selects a stretch |
| `<audio-ui-timeline-playhead>` | A mark at the position, on the lane it sits in |
| `<audio-ui-timeline-mark>` | Something at a `value`, such as a bar number. With `movable`, a drag moves it, firing `markinput` and `markchange` |
| `<audio-ui-timeline-range>` | A loop or a selection, its `value` as `"start end"`: drag it, resize it with an `<audio-ui-timeline-range-handle>` per `edge`, or with `drawable`, draw one across the empty lane. It fires `rangeinput` and `rangechange` with `{ value, edge, reason }` |
| `<audio-ui-timeline-navigator>` | The whole timeline as a bar: drag its `<audio-ui-timeline-navigator-window>` to scroll, one of its `<audio-ui-timeline-navigator-handle>`s to zoom, double-click to show everything |
| `<audio-ui-timeline-track>` | A row of a header beside a lane, its `height` in px: an `<audio-ui-timeline-track-resize-handle>` changes it, firing `heightinput` and `heightchange`. `<audio-ui-timeline-track-header>` stays at the left edge as the lane scrolls |
| `<audio-ui-timeline-clip>` | A stretch of a source: `start`, `length`, `offset`, `fade-in` and `fade-out` (with `fade-in-shape` and `fade-out-shape`), `source-length`. A press on its body selects it (`clipselect`, then `selected`) and puts the cursor there; Delete fires `clipremove`. It fires `clipinput` and `clipchange` with `{ value, reason, target, lane, delta, copy }` |
| `<audio-ui-timeline-clip-header>` | Dragging it moves the clip, over other lanes too |
| `<audio-ui-timeline-clip-handle>` | Trims the clip's `edge`, moving where in the source it begins rather than stretching it |
| `<audio-ui-timeline-clip-fade-handle>` | Sets the fade at its `edge` (`in` or `out`); a double click or Enter steps its shape |
| `<audio-ui-timeline-clip-fade>` | Draws the fade at its `edge` over the clip, shaded by `--clip-fade-shade` |

### Piano roll

`<audio-ui-piano-roll>` edits notes on a timeline: it sits inside an `<audio-ui-timeline>`, which gives it its length, zoom, grid and position, and importing it registers the timeline and the piano too. Its notes are its `value` property, `{ id, pitch, start, length, velocity?, chance?, muted? }[]`, and its selection its `selection` property. The rows, the notes and the velocity bars are made from them:

```html
<audio-ui-timeline duration="16" snap-step="0.25">
  <audio-ui-piano-roll mode="draw">
    <audio-ui-piano-roll-keys>
      <audio-ui-piano aria-label="Keys"><audio-ui-piano-keys></audio-ui-piano-keys></audio-ui-piano>
    </audio-ui-piano-roll-keys>
    <audio-ui-timeline-viewport>
      <audio-ui-piano-roll-grid aria-label="Notes">
        <audio-ui-piano-roll-rows></audio-ui-piano-roll-rows>
        <audio-ui-piano-roll-notes></audio-ui-piano-roll-notes>
        <audio-ui-timeline-playhead></audio-ui-timeline-playhead>
      </audio-ui-piano-roll-grid>
    </audio-ui-timeline-viewport>
  </audio-ui-piano-roll>
</audio-ui-timeline>
```

<TypeTable>
<TypeRow name={"min-pitch"} type={"number"} default={"48"}>The lowest row, a MIDI pitch: 60 is middle C.</TypeRow>
<TypeRow name={"max-pitch"} type={"number"} default={"72"}>The highest row.</TypeRow>
<TypeRow name={"folded"} type={"string"}>Present, only the pitches carrying notes get a row; `"scale"`, those in the scale as well.</TypeRow>
<TypeRow name={"scale"} type={"string"}>The scale whose rows are marked `data-in-scale`: `major`, `minor`, `dorian`… with `scale-root`, 0 for C.</TypeRow>
<TypeRow name={"mode"} type={"string"} default={"select"}>What a press on empty grid does: start a selection rectangle, or `draw` a note.</TypeRow>
<TypeRow name={"draw-style"} type={"string"} default={"stretch"}>In draw mode, `paint` draws a note in each grid cell a drag crosses.</TypeRow>
<TypeRow name={"min-length"} type={"number"}>The shortest a note can be. Defaults to the timeline's grid step.</TypeRow>
<TypeRow name={"active-pitches"} type={"string"}>Pitches lit from elsewhere, separated by spaces: a MIDI input, the notes playing.</TypeRow>
<TypeRow name={"disabled"} type={"boolean"}></TypeRow>
</TypeTable>

Editing the notes fires `input` and `change` with `{ value, reason }`; a new selection fires `noteselect` with `{ selection, reason }`; a pitch that should sound fires `noteon`, which `preventDefault()` keeps silent, and `noteoff`. The `getNoteLabel(note)` property names each note, "C4, 4 to 6" by default.

| Part | What it is |
| --- | --- |
| `<audio-ui-piano-roll-grid>` | The surface notes are drawn on, a timeline lane that takes focus: Enter adds a note at the position, Escape clears the selection, Cmd/Ctrl+A selects every note, and Cmd/Ctrl+D, C, X, V and Q repeat, copy, cut, paste and quantize |
| `<audio-ui-piano-roll-rows>` | Makes an `<audio-ui-piano-roll-row>` per pitch, highest first: a band across the grid with `data-color`, `data-in-scale`, `data-octave` and `data-active` |
| `<audio-ui-piano-roll-notes>` | Makes an `<audio-ui-piano-roll-note>` per note, in reading order, from its `<template>`: a toggle button placed at its start and pitch, which moves by dragging and from the keys, with `--piano-roll-velocity` and `--piano-roll-chance` |
| `<audio-ui-piano-roll-note-handle>` | Inside a note, drags its `edge` to change its length |
| `<audio-ui-piano-roll-marquee>` | The selection rectangle being dragged |
| `<audio-ui-piano-roll-selection-span>` | The time the selection covers; an `<audio-ui-piano-roll-stretch-handle>` per `edge` stretches it |
| `<audio-ui-piano-roll-velocity-lane>` | A lane of bars, one per note through `<audio-ui-piano-roll-velocities>`, for its velocity or with `level="chance"` its chance to play. Each `<audio-ui-piano-roll-velocity>` is as tall as `--piano-roll-level` and holds a native range input |
| `<audio-ui-piano-roll-keys>` | Lays the `<audio-ui-piano>` it holds on the roll's rows: a key sounds through the roll, and with Shift selects the notes on its row |
