Copy a styled component into a shadcn project with its CLI, as the rest of this guide sets up:

```bash
npx shadcn@latest add @audio-ui/knob
```

Or, without shadcn/ui, install the headless primitives and style them yourself: [React](/docs/react) shows each one's parts.

```bash
npm install @audio-ui/react
```

</TabsContent>

<TabsContent value="vue">

Install the custom elements:

```bash
npm install @audio-ui/elements
```

Declare the tags as custom elements to Vue's compiler, in `vite.config.ts`:

```ts
vue({
  template: {
    compilerOptions: { isCustomElement: (tag) => tag.startsWith("audio-ui-") },
  },
});
```

Then register the elements the app uses, once, and bind a value with `v-model`. [Vue](/docs/elements/vue) has the template types and the rest.

```ts
import "@audio-ui/elements/knob";
```

</TabsContent>

<TabsContent value="svelte">

Install the custom elements:

```bash
npm install @audio-ui/elements
```

Svelte renders the tags as they are written. Register the elements the app uses, once, and bind a value with `value` and `oninput`. [Svelte](/docs/elements/svelte) has the template types and the rest.

```ts
import "@audio-ui/elements/knob";
```

</TabsContent>

<TabsContent value="web">

Install the custom elements:

```bash
npm install @audio-ui/elements
```

Import an entry once, before the elements are used: it registers them, and the markup upgrades as the module loads. [Custom elements](/docs/elements) has every element, its attributes and its events.

```html
<audio-ui-knob min="0" max="100" value="40">
  <audio-ui-knob-control>
    <audio-ui-knob-track></audio-ui-knob-track>
    <audio-ui-knob-indicator></audio-ui-knob-indicator>
    <audio-ui-knob-thumb></audio-ui-knob-thumb>
  </audio-ui-knob-control>
</audio-ui-knob>

<script type="module">
  import "@audio-ui/elements/knob";
</script>
```

</TabsContent>

## Prerequisites

audio/ui is built on **React 19** and [Tailwind CSS v4](https://tailwindcss.com). Set up both first. The [shadcn/ui installation guide](https://ui.shadcn.com/docs/installation) covers the environment.

## Setup the audio/ui Registry

Add the audio/ui registry namespace to your `components.json` and set your component library and style. See the [shadcn registry docs](https://ui.shadcn.com/docs/registry) for the registry config.

```json
{
  "registries": {
    "@audio-ui": "https://www.audio-ui.dev/r/{style}/{name}.json"
  }
}
```

## Components

You can install audio/ui using the [**shadcn CLI**](https://ui.shadcn.com/docs/cli) for automation or by manual installation for full control. Both methods apply to everything in [Docs](/docs/) and the [component catalog](/components), including the `block-*` blocks and demos you install with `@audio-ui/…`.

### The package a component needs

Some components import from `@audio-ui/core` (pitch, MIDI, musical time, analysis). Installing one adds the package to your `package.json` if it is not there, with no version pinned: the version is yours to choose.

The CLI leaves a version you already have. If an older `@audio-ui/core` is installed and a component needs a subpath it did not have yet, your build says it cannot resolve `@audio-ui/engine/time` (or `/pitch`, `/midi`, `/analysis`). Update the package:

```bash
npm install @audio-ui/core@latest
```

If your package manager still resolves the old version, bypass its cache: with Bun, add `--no-cache`.

## Styling

Components are styled with a design token system defined by CSS variables and implemented with Tailwind CSS, following the same conventions as shadcn/ui so they're fully customizable. See the [Styling guide](/docs/styling) for details.
