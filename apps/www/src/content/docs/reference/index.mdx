audio/ui is two things that meet at the registry: published packages that hold the logic and the behavior, and a registry of source files you install and own, which hold the appearance and the Web Audio glue. Every piece has one home, and a new feature is a composition of pieces that are already there.

## Layers

| Layer | What it holds | Where |
| --- | --- | --- |
| Core | Domain models and their pure logic: values and scales, the time of a song, notes, a device's description (`defineDevice`), the primitives' controllers. No framework, no Web Audio | `@audio-ui/core` |
| Primitives | Headless, accessible React parts over the core | `@audio-ui/react` |
| Libraries | Framework-free modules: an engine's building blocks, the arrangement and its editing, files and formats. Each takes an audio context as a parameter | `lib/` in your project ([Libraries](/docs/reference/libraries), [Utilities](/docs/reference/utilities)) |
| Hooks | React's side of a library: lifecycle, subscriptions, the page's context | `hooks/` ([Hooks](/docs/reference/hooks)) |
| Devices | An effect or an instrument as three files: its state (`device.ts`), its Web Audio engine (`engine.ts`), its face (`panel.tsx`) | `components/audio-ui/devices/<name>/` |
| Elements and panels | Appearance over the primitives, never behavior | `components/audio-ui/` |
| Blocks | Screens composed of all of the above | `components/examples/` |

A layer only reaches down: a hook uses libraries, a library never imports a hook, an element never makes sound. The audio logic itself (filters, dynamics, pitch, codecs) comes from [audio.js](https://audio.js.org) atoms; audio/ui holds the interface and the glue between them.

## Where an audio context comes from

One rule, everywhere:

- An engine or a library takes the context as a parameter (`createDelayEngine(ctx, state)`), so it also runs on an `OfflineAudioContext`, for an export or a measurement.
- A hook given a node (a destination, an analyser) works on that node's context: the graph it plays into.
- Everything else, a block or a hook that starts sound from nothing, asks [`webAudio`](/docs/engine/output) for the page's one context, and resumes it with `webAudio.resume()` in the gesture that starts sound. Nothing makes a context of its own.

## Who owns state

Each thing that changes over time has one source of truth:

- An engine object owns what plays: its nodes, its worklet, whether it is loaded. React state only mirrors what the screen shows.
- A pure reducer owns an edit: the arrangement is `apply(state, command)`, so an undo is a value.
- A value that moves every frame (a playhead, a level, a spectrum) is a live source (`createSource`) a component reads, never a React state set every frame.
- An engine that loads something exposes `ready`, and nothing is built on a load once the engine is disposed.

## A new device, composed

1. Describe it with `defineDevice` (`@audio-ui/core/device`): its parameters, ranges and defaults. The panel, the engine and an agent's tools all read this one description.
2. Write its settings as a pure function of its state, the numbers that go on the nodes, so they are read and tested without an audio context.
3. Write its engine as an [`EffectEngine` or an `InstrumentEngine`](/docs/reference/factories#engine-contracts), from the pieces of [`device-engine`](/docs/reference/factories#device-engine): a worklet stage, a feed, shared noise. Its DSP comes from an audio.js atom.
4. Give it a face with `DevicePanel`, which makes a control for each parameter.
5. List it in the [device library](/docs/reference/registries#the-device-library) and in the registry with [`deviceItems`](/docs/reference/registries#the-shadcn-registry).

A block then plays it with [`useDeviceLoop`](/docs/reference/factories#usedeviceloop) (an effect) or [`usePolyphony`](/docs/reference/factories#usepolyphony) (an instrument), and a host puts it on a track through the library.
