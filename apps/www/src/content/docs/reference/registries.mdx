description: "Where reusable things are listed and found: the device library a host builds tracks from, and the shadcn registry every component, hook and lib installs from."
---

Two registries, two jobs. The device library is code that runs in your app: it turns the device ids a project stores into engines. The shadcn registry is what installs: each component, hook and lib as source files in your project.

## The device library

```bash
npx shadcn@latest add @audio-ui/device-library
```

Every device with its engine and the shelf it sits on, by its stable id. A host stores ids (`audioui.compressor`), never panels or engines, and builds a track's chain from them.

```ts
import { DEVICE_SHELVES, libraryDevice } from "@/lib/device-library";

const entry = libraryDevice("audioui.compressor");
const engine = entry?.create(ctx, entry.device.defaults(), { tempo });

for (const shelf of DEVICE_SHELVES) {
  // shelf.label, shelf.devices: what a device browser lists.
}
```

<TypeTable title="LibraryDevice">
<TypeRow name={"device"} type={"Device"}>Its description, from `defineDevice`.</TypeRow>
<TypeRow name={"create"} type={"EngineFactory<AnyDeviceState, LibraryEngine>"}>Makes its engine: an `EffectEngine` or an `InstrumentEngine`.</TypeRow>
<TypeRow name={"shelf"} type={"string"}>Instruments, Dynamics, Tone, Distortion, Space, Motion or Utility.</TypeRow>
<TypeRow name={"mono"} type={"boolean | undefined"}>An instrument whose engine takes every note, gliding from one to the next, instead of one engine per voice.</TypeRow>
</TypeTable>

`LibraryEngine` is the two engine contracts held side by side: what both share, an effect's input and key where it has them, an instrument's notes where it has them. A note reaches an instrument of the library through `createVoicePool`, which gives it one engine per voice ([`voice-pool`](/docs/reference/libraries)), or the one engine of a mono instrument.

A device of your own joins the library with the same pairing: its description and its engine factory, checked against each other.

## The shadcn registry

Everything installs with `npx shadcn@latest add @audio-ui/<name>`, to a place that depends on what it is:

| Item | Lands in | Imported as |
| --- | --- | --- |
| An element or a panel | `components/audio-ui/` | `@/components/audio-ui/<name>` |
| A device's state, engine or panel | `components/audio-ui/devices/<name>/` | `@/components/audio-ui/devices/delay/engine` |
| A hook | `hooks/` | `@/hooks/<name>` |
| A lib | `lib/` | `@/lib/<name>` |
| A block or a demo | `components/examples/` | the screen itself |

An item names what it needs, so installing one brings the rest: `registryDependencies` for other items, `dependencies` for npm packages. A device installs as four items: `<name>-device`, `<name>-engine`, `<name>-panel`, and `<name>` for all three.

A name that is retired keeps working: its item has no file of its own and installs what replaced it, and its description says so (`Gone:`, `Renamed to`, `Moved to @audio-ui/core`). `use-simulated-clock` installs `use-transport-clock`, for one.

### Declaring items

In the repository, every `_registry.ts` declares its items through the factories of `registry-audio/bases/items.ts`, which write a file's path, its target and its type once:

```ts
import { deviceItems, hookItem, libItem } from "../../items";

libItem("polyphony", { dependencies: ["@audio-ui/core"], description: "…" });
hookItem("use-polyphony", { description: "…", registryDependencies: ["@audio-ui/polyphony"] });

// A device's four items from one description: its engine always gets device-engine,
// its panel device-panel and @audio-ui/react, both its state.
...deviceItems("delay", {
  device: { dependencies: ["@audio-ui/core"], description: "…", kernels: true },
  engine: { description: "…", registryDependencies: ["@audio-ui/audio-worklet"] },
  panel: { categories: ["device", "plot", "knob"], description: "…" },
});
```

The tables of [Hooks](/docs/reference/hooks), [Libraries](/docs/reference/libraries) and [Utilities](/docs/reference/utilities) are read from these declarations, and a check fails when a hook or a lib is listed on none of them.
