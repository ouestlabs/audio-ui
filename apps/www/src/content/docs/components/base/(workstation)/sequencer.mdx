A step grid for a drum pattern or any row of on and off steps, with a velocity bar under each. The registry component is written on the sequencer primitive, which installs with it.

</ForFrameworks>

<ForFrameworks only="vue svelte web">

The sequencer's behavior is one file, the primitive, written on the UI SDK kernel and copied into your project. It is a grid of steps to switch on and off, one row for each sound, as in a drum machine, with a velocity bar under each step. It holds two values, the pattern and the velocities. Each framework renders it with a thin adapter that you also own, and one suite of tests runs against each adapter.

</ForFrameworks>

## Usage

<ForFrameworks only="react">

```tsx
import { Sequencer } from "@/components/audio-ui/sequencer";

<Sequencer
  aria-label="Drum pattern"
  onValueChange={setPattern}
  rowLabels={["Kick", "Snare", "Hihat"]}
  source={step}
  value={pattern}
/>;
```

`value` is a row per sound, each a list of steps: `boolean[][]`. `velocities` is how loud each step plays, from 0 to 1, in the same shape; a step it does not list plays at full. Add `showVelocity` for a bar under each row to draw them. `source` is the step being played, a live `{ getSnapshot, subscribe }` such as one made with `createSource`: a clock ticking every step never re-renders React.

</ForFrameworks>

<ForFrameworks only="react">

The primitive alone, part by part:

</ForFrameworks>

A Root groups the rows. A Row is one sound, a Cell one of its steps, a `<button>` pressed when the step is on, and a Velocity a bar under a step. You write a Row for each row and a Cell for each step, with their `row` and `step`: the Root's content can read the state, `{ rows, steps }`, so the grid follows the pattern. That is a function in React, the default slot in Vue and a snippet in Svelte.

```tsx
import { Sequencer } from "@/components/audio-ui/sequencer/react";

const KIT = ["Kick", "Snare", "Hat"];

export function Beat({ pattern, onChange }: { pattern: boolean[][]; onChange: (pattern: boolean[][]) => void }) {
  return (
    <Sequencer.Root onValueChange={onChange} value={pattern}>
      {({ rows, steps }) =>
        Array.from({ length: rows }, (_, row) => (
          <Sequencer.Row aria-label={KIT[row]} className="flex gap-1" index={row} key={row}>
            {Array.from({ length: steps }, (_, step) => (
              <Sequencer.Cell
                aria-label={`${KIT[row]}, step ${step + 1}`}
                className="size-8 rounded bg-muted data-on:bg-primary data-current:ring-2"
                key={step}
                row={row}
                step={step}
              />
            ))}
          </Sequencer.Row>
        ))
      }
    </Sequencer.Root>
  );
}
```

In the web adapter the sequencer makes the rows, the cells and the velocity bars itself, one for each step of its pattern. Add the `velocity-bars` attribute to get the bars.

**Velocity bars.** Write a Velocity for each step, in the Row, under the cells. Its height is the `--sequencer-velocity` CSS variable, from 0 to 1, which you read in your styles. It holds a native `<input type="range">` that carries its name and takes the keys.

### The step being played

Give the Root a `source`, a live value of the step being played, in the shape of an external store: `getSnapshot()` returns the step and `subscribe(listener)` is called on each tick. The step's cells get `data-current` straight in the DOM, so a clock ticking every step renders nothing. Any object with those two methods works, with nothing to install, and `useTransportClock` from the registry gives you one on the audio clock.

In the web adapter, `source` is a property, not an attribute.

`Sequencer` takes the `Root` props, plus:

<TypeTable>
<TypeRow name={"rowLabels"} type={"string[]"}>Names written beside each row, and its accessible name.</TypeRow>
<TypeRow name={"beatEvery"} type={"number"} default={"4"}>Highlights every nth step.</TypeRow>

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter, the grids as JSON).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `boolean[][]` | | The pattern: a row for each sound, each a list of steps. Controlled, or the starting one. |
| `velocities`, `defaultVelocities` | `number[][]` | | How loud each step plays, from 0 to 1, a row for each sound like the pattern. A step it does not list plays at full. |
| `source` | `{ getSnapshot, subscribe }` | | The step being played, followed with no render. |
| `disabled` | `boolean` | `false` | Takes no gesture. |
| `onValueChange` | `(pattern, details) => void` | | A step is flipped. `details.cancel()` keeps the pattern as it was. |
| `onValueCommitted` | `(pattern, details) => void` | | A press, a paint or a key that changed the pattern ends. |
| `onVelocityChange` | `(velocities, details) => void` | | A velocity is drawn or nudged. |
| `onVelocityCommitted` | `(velocities, details) => void` | | A drag, a key or a reset that changed a velocity ends. |

### What a change reports

- Pattern: `reason` is `"press"`, `"paint"` or `"keyboard"`.
- Velocities: `reason` is `"drag"`, `"keyboard"`, `"input-change"` or `"reset"`.
- Both carry a `source` (`"mouse"`, `"touch"`, `"pen"`, `"keyboard"`) and the `event`.
- In the web adapter, the pattern is the `input` and `change` events, and the velocities the `velocitychange` and `velocitycommit` events, with `detail: { value, reason, source }`.

### States to style from

- `data-on` and `aria-pressed` on a cell while its step is on, `data-current` while it is the step being played, `data-row` and `data-step` for its place.
- `data-painting` on the Root and the cells while a pointer paints.
- `data-disabled` on every part.
