Plays or shows notes, for a virtual instrument, a MIDI visualizer or a chord reference. The registry component is written on the `Piano` primitive of `@audio-ui/primitives`, which installs with it and draws white and black keys for any MIDI range.

</ForFrameworks>

<ForFrameworks only="vue svelte web">

The piano's behavior is one description, `piano` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. A key sounds while it is pressed, by pointer or from the keyboard, and dragging across the keys glides from one to the next. Each framework renders it with a thin adapter that you copy into your project and own, and one suite of tests runs against each adapter.

</ForFrameworks>

## Overview

- **Range:** `minPitch` and `maxPitch` are MIDI pitches (default `48` and `72`, C3 to C5), or `pitches` lists the exact keys to show. Key colors and layout follow the chromatic pattern.
- **Events:** `onNoteOn(pitch, eventDetails)` and `onNoteOff(pitch, eventDetails)` report MIDI pitches, ready for an audio engine. `eventDetails.reason` says how the note started (`"press"`, `"glide"` or `"keyboard"`), and `eventDetails.cancel()` in `onNoteOn` keeps the key silent.
- **Pointer:** press and hold a key to hold its note. Drag across keys for a glissando: each key plays as the pointer crosses it. Each touch holds its own key, so chords work on a touch screen.
- **External notes:** `activeNotes` lights keys from outside, such as a MIDI input or a sequencer's current chord, without calling `onNoteOn` or `onNoteOff`.
- **Accessibility:** each key is a button named after its pitch ("C4"), behind one tab stop. The arrow keys move between keys, and Space or Enter holds the focused key until it is released.
- **Layout:** the primitive can also lay keys out vertically (`orientation="vertical"`, lowest key at the bottom) or in equal widths (`layout="even"`). The piano roll's keyboard uses this.

## Usage

<ForFrameworks only="react">

```tsx
import { Piano } from "@/components/audio-ui/piano";
```

**Note events:**

```tsx
<Piano
  maxPitch={72}
  minPitch={48}
  onNoteOff={(pitch) => synth.release(pitch)}
  onNoteOn={(pitch) => synth.trigger(pitch)}
/>
```

**External notes (MIDI input, a sequencer's current chord):**

```tsx
<Piano activeNotes={midiInputNotes} maxPitch={72} minPitch={48} />
```

**A MIDI keyboard:** `useMidiInput` listens to the page's MIDI input. Browsers ask for permission, so connect it from a click: with `requestAccess`, or the ready-made button, `npx shadcn@latest add @audio-ui/midi-connect-control`.

```tsx
import { useMidiInput } from "@/hooks/use-midi-input";

const midi = useMidiInput({
  onNoteOff: (pitch) => synth.release(pitch),
  onNoteOn: (pitch, velocity) => synth.trigger(pitch, velocity),
});

<button onClick={midi.requestAccess} type="button">Connect MIDI</button>
<Piano activeNotes={midi.activeNotes} maxPitch={72} minPitch={48} />
```

Everything `useMidiInput` gives is in [Input](/docs/guides/input).

A Root is the keyboard, and a Key is one key, a `<button>` placed along it for its `pitch` and named by its note, such as "C4". A Label inside a Key writes that name for you to style. You write a Key for each pitch: the Root's content can read the state, whose `pitches` lists them lowest first, so the keys follow `minPitch`, `maxPitch` and `pitches`. That is a function in React, the default slot in Vue and a snippet in Svelte.

**Give the Root its size.** The keys are placed with percentages, so a Root with no height or width has nothing to place them in.

In the web adapter, the keyboard makes a key for each pitch, each a wrapper around a `<button>`. To style or fill them yourself, write the `audio-ui-piano-key` elements with a `pitch` and a button inside: the keyboard then leaves them as they are, and an `audio-ui-piano-label` inside a button gets its note.

### What a note reports

- `onNoteOn` gets `velocity` from 0 to 1, a `reason` (`"press"`, `"glide"` or `"keyboard"`), a `source` and the `event`.
- `onNoteOff` gets a `reason`: `"press"`, `"glide"` or `"keyboard"`.
- In the web adapter, they are the `noteon` and `noteoff` events, with `detail: { value, reason, source, velocity }`, where `value` is the pitch.

## Interaction

### Pointer

<KeyTable title="Behavior">
<KeyRow gesture={"Press a key"}>Fires `onNoteOn`; the key stays pressed while held.</KeyRow>
<KeyRow gesture={"Release"}>Fires `onNoteOff`.</KeyRow>
<KeyRow gesture={"Drag across keys"}>Glissando: the previous key releases (`onNoteOff`) and the next one sounds (`onNoteOn`) as the pointer crosses it.</KeyRow>
<KeyRow gesture={"Multiple pointers"}>Each pointer (finger) holds its own key, so chords work on touch devices.</KeyRow>
</KeyTable>

### Keyboard

The keys share one tab stop. On the focused key:

<KeyTable title="Keys">
<KeyRow gesture={"`ArrowLeft` / `ArrowRight` (or `ArrowDown` / `ArrowUp`)"}>Move focus to the next lower / higher key</KeyRow>
<KeyRow gesture={"`Shift` + arrow, `PageDown` / `PageUp`"}>Move focus an octave down / up</KeyRow>
<KeyRow gesture={"`Space` / `Enter`"}>Hold the focused key: `onNoteOn` on press, `onNoteOff` on release</KeyRow>
<KeyRow gesture={"`Home` / `End`"}>Move focus to the lowest / highest key</KeyRow>
</KeyTable>

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `minPitch`, `maxPitch` | `number` | `48`, `72` | The lowest and highest MIDI pitch, inclusive: 60 is middle C. |
| `pitches` | `number[]` | | Only these pitches get keys, instead of `minPitch` to `maxPitch`. |
| `layout` | `"keyboard"` or `"even"` | `"keyboard"` | Like a piano, with the black keys between the white ones, or one equal share for each key, as the rows of a piano roll are. |
| `orientation` | `"horizontal"` or `"vertical"` | `"horizontal"` | Which way the keys run. A vertical keyboard puts the low end at the bottom. |
| `activeNotes` | `number[]` | | Pitches lit from elsewhere, such as a MIDI input or a sequencer, on top of the keys pressed here. |
| `disabled` | `boolean` | `false` | Plays nothing. |
| `onNoteOn` | `(pitch, details) => void` | | A key sounds. `details.cancel()` keeps it silent. |
| `onNoteOff` | `(pitch, details) => void` | | A key is released, the pointer glides off it, or it loses focus while held. |

### States to style from

- `data-active` on a key while it sounds, pressed here or listed in `activeNotes`.
- `data-color` on a key, `"black"` or `"white"`, `data-disabled`, `data-layout` and `data-orientation`.
