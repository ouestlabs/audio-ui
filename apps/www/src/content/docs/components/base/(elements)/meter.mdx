Shows audio levels for a stereo output, a channel strip or any multi-channel source. The registry component is written on the `Meter` primitive of `@audio-ui/primitives`, which installs with it: one bar per channel, a destructive color when a channel clips, and an optional peak-hold mark. The meter only displays levels: it takes no pointer or keyboard input, and no focus.

## Overview

- **Value:** one dB reading per channel (stereo is `[left, right]`), from the `value` prop or a live [`source`](#feeding-real-levels). The number of readings sets the number of channels.
- **Peak hold:** an optional peak level per channel places a peak-hold mark. The primitive has no clock: your [source](#feeding-real-levels), Tone.js or another library computes the peak and its decay.
- **Clipping:** channels at or above `clipThreshold` (default `0` dB) get `data-clipping`, to style a clip indicator.
- **Accessibility:** each channel is a `role="meter"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax` and a value text in dB ("-6 dB"). It is not an `aria-live` region, so screen readers read the level when asked instead of announcing every update. `aria-label` names the group; with several channels, each is named "… 1", "… 2".


**With a peak-hold mark:**

```tsx
<Meter peak={[-4, -8]} value={[-9, -14]} />
```

## Feeding real levels

`value` and `peak` are plain props: fine for static or slowly changing levels, but a signal sampled 60 times a second would re-render React on every frame. For live audio, pass a `source` instead: the meter subscribes to it and writes each frame to the DOM, without a React render.

A source is any object with the shape of an external store, so you can bring your own (Tone.js, a worklet, a WebSocket):

```ts
interface MeterSource {
  getSnapshot: () => { levels: readonly number[]; peaks?: readonly number[] };
  subscribe: (listener: () => void) => () => void;
}
```

`createSource` from `@audio-ui/core` makes one you push to. The `use-audio-levels` hook is one: it samples the RMS level of one `AnalyserNode` per channel every animation frame, how loud the signal sounds, and lets it fall back smoothly; its peak is the loudest sample, held a moment before it falls, so the mark shows how near the signal comes to clipping.

```bash
npx shadcn@latest add @audio-ui/use-audio-levels
```

```tsx
import { Meter } from "@/components/audio-ui/meter";
import { useAudioLevels } from "@/hooks/use-audio-levels";

// One analyser per channel, made once: a new array restarts the sampling.
const analysers = useMemo(() => {
  const analyser = ctx.createAnalyser();
  output.connect(analyser); // a tap: the analyser plays nothing
  return [analyser];
}, [ctx, output]);

const levels = useAudioLevels(analysers);

<Meter aria-label="Output" source={levels} />;
```

For a stereo meter, split the signal with a `ChannelSplitter` and give the hook one analyser per side. The hook and the other analysis tools are in [Analysis](/docs/guides/analysis).

To read the levels in React as well, for a numeric readout for example, use `useSyncExternalStore(levels.subscribe, levels.getSnapshot)`.

### Usage

A Root groups the channels. Each Channel has an `index`, the position of its level, and holds an Indicator that grows with the level, a Peak mark, a Value for the text and a Label that names it. Marks sit along the length, beside the channels. You write the channels yourself, one for each level.

The Root's content can read the meter's state, `{ channelCount, orientation }`, so the channels follow the count of a live source: a function in React, the default slot in Vue, a snippet in Svelte.

The Indicator is scaled from the bottom of a vertical meter and from the start of a horizontal one: give the Channel its size and `position: relative`, and the Indicator `position: absolute` with the color. The Peak is placed by `bottom` or `left`, and hidden while its channel has no peak. A Value takes the formatted level as its text, or a function of the state in React, a slot in Vue and a snippet in Svelte, which reads `text`, `valueNow` and the zone the level is in.

### A live source

An engine updates levels 60 times a second, which is too often to render. Give the Root a `source` instead of `value`: the meter writes each frame straight to the elements of its channels, from one subscription for all of them, and the framework never renders for it.

```ts
import { createSource } from "@audio-ui/core";
import type { MeterFrame } from "@audio-ui/core/meter";

const source = createSource<MeterFrame>({ levels: [-30, -30], peaks: [-6, -6] });

// From the engine's frame loop:
source.set({ levels: [-22.4, -19.8], peaks: [-6, -6] });
```

Any object with `getSnapshot()` returning `{ levels, peaks? }` and `subscribe(listener)` works. The levels, the peak marks, `aria-valuenow`, `aria-valuetext` and the Value's text are written on each frame, and a clip is kept: the channel and its Indicator carry `data-clipped` from the first level at or above the clip threshold until a click on the meter clears it, as in a DAW. A source that changes its number of channels renders the channels again, and only then. In the web adapter, `source` is a property, not an attribute.

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value` | `number[]` | | The level of each channel, in dB. Its length is the channel count. |
| `peak` | `number[]` | | The peak-hold level of each channel. Timing and decay live outside the primitive. |
| `source` | `{ getSnapshot, subscribe }` | | A live signal, painted with no render. It takes precedence over `value` and `peak`. |
| `min`, `max` | `number` | `-60`, `6` | The range, in dB. |
| `orientation` | `"vertical"` or `"horizontal"` | `"vertical"` | Which way the bars run. |
| `scale` | `"linear"`, `"iec"` or a function | `"linear"` | How levels are spread along the length. `"iec"` gives the top more room, as digital peak meters do; a function is any increasing curve of the level. |
| `clipThreshold` | `number` | `0` | The level at or above which a channel is clipping. |
| `warnThreshold` | `number` | | The level at or above which a channel is in its warning zone, below the clip threshold. Unset, there is no warning zone. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | one decimal | How a level is written, for the Value and for `aria-valuetext`. |

The Mark takes a `value` and sits along the length at its level. A Channel takes `getAriaValueText(formatted, value, index)` to announce its level in your own words, like `"-6 dB"`. A function `scale` is a property: in the web adapter, set it from script.

### States to style from

- `data-orientation` on the Root, the channels, the Indicators, the Peaks and the Marks.
- `data-warning` and `data-clipping` on a channel, its Indicator and its Peak, while its level is in the warning zone or at or above the clip threshold.
- `data-clipped` on a channel and its Indicator, with a live source, from the first clip until a click on the meter.

### Accessibility

Each channel is a `role="meter"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax` and an `aria-valuetext` that reads the level as a number with its unit, not as a share of the range. Name it with `aria-label`, or with a Label part inside it, which sets `aria-labelledby`. The Indicator, the Peak and the Value are hidden from assistive technology: the channel announces its own level.
