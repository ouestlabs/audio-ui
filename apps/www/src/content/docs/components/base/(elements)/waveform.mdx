Components for drawing audio. `Waveform` shows a whole file and lets you scrub through it. `LiveWaveform` follows a signal as it plays. `BarVisualizer` turns that signal into a few bars you style in CSS. All three are written on the waveform primitive, which installs with them and works with any audio: decoded PCM samples, a microphone or a stream from your server.

</ForFrameworks>

<ForFrameworks only="vue svelte web">

The waveform's behavior is a few files, the primitive, written on the UI SDK kernel and copied into your project. It shows the shape of audio, from `peaks` known upfront or from a live `levels` signal, and follows a playback position that can be seeked. Each framework renders it with a thin adapter that you also own, and one suite of tests runs against each adapter.

</ForFrameworks>

## Overview

- **Two kinds of data:** a file's shape is known in advance, so `Waveform` takes `values` (amplitudes from `0` to `1`, at any resolution). A live signal is not, so `LiveWaveform` and `BarVisualizer` take a [`source`](#live-signals) and follow it outside React.
- **Value:** `value` is the playback position, from `0` to `duration` (default `1`, a fraction; pass the track length in seconds to work in seconds). The primitive owns the seek position, not the audio: connect `onValueChange` to your own `<audio>` element.
- **Asymmetric shape:** give `values` the lowest and highest sample of each slice (`{ min, max }`) and the waveform is drawn asymmetric, as in a DAW. Plain amplitudes draw the same shape above and below the middle.
- **Part of the audio:** `range` shows only a stretch of the audio, such as a clip's window onto its source or a zoomed view. The playhead, seeking, hover, regions and markers follow that stretch. See [Showing part of the audio](#showing-part-of-the-audio).
- **Resolution:** the canvas draws as many bars as fit its width and keeps the loudest sample of each bar's slice, so detail holds at any size. Bars align to physical pixels, so their edges stay sharp at any pixel density or zoom. See [Feeding real audio](#feeding-real-audio).
- **Shapes:** `shape="mirror"` (the default) centers the bars, `"bars"` stands them on the baseline, and `"line"` joins the levels into one shape. A live waveform can also be a `"scope"`: raw samples traced as one line, like an oscilloscope.
- **On the timeline:** [`WaveformRegion`](#regions-and-markers) is a stretch you can move and resize, such as a loop. `WaveformMarker` is a labelled point. `WaveformHover` follows the pointer and shows the time under it.
- **Performance:** moving parts are painted outside React, and only when something changes. A waveform that is off screen or at rest uses no frames. When reduced motion is requested, live waveforms repaint a few times per second, without smoothing or idle animation.
- **Accessibility:** the seekable waveform holds a native `<input type="range">`: it takes focus, carries `aria-label`, announces the played share (or the text from `getAriaValueText`, such as a time), and supports the arrow keys, <kbd>Home</kbd>, <kbd>End</kbd>, <kbd>Page Up</kbd> and <kbd>Page Down</kbd>. Each region handle holds one too. Live waveforms are images: give them an `aria-label`.

A Root owns the position and what is shown. Everything else is a part you place in it:

- **Canvas**: draws the shape on the device pixel grid, sharp at any density, and only when something changed.
- **Bars** and **Bar**: the shape as a fixed number of elements, styled in plain CSS from `--waveform-level`.
- **Control**: the seekable surface. A press jumps to the pointer and a drag scrubs. It holds the native `<input type="range">` that takes focus and the keys, and carries the accessible name.
- **Playhead** and **Thumb**: follow the position through the `--waveform-position` CSS variable.
- **Hover**: shown at the hovered point, with the text `format` returns.
- **Marker**: a point of interest at a `value`.
- **Region** and **RegionHandle**: a named stretch laid over the waveform, moved by its body and resized by its edges.

### A live position and a live signal

Give the Root a `source`, a live position in `duration` units in the shape of an external store: `getSnapshot()` returns it and `subscribe(listener)` is called on each tick. The `--waveform-position` variable, the Canvas and the input follow it straight in the DOM, with no render. `levels` is the same for a signal, such as a microphone or an analyser: each value is a level from 0 to 1, and while it is audible the Root carries `data-active`. Any object with those two methods works, with nothing to install.

<ForFrameworks only="react">

## Feeding real audio

`values` is a plain prop: the component does not decode audio. `@/lib/engine/analysis` and the `audio-decode` lib (`npx shadcn@latest add @audio-ui/audio-decode`) turn a real audio file into `values`: `decodeAudioChannels` (from `audio-decode`) reads every channel's PCM samples at the context's sample rate, with the browser's own decoder, or for an AIFF, CAF or Apple Lossless file it refuses, as Chrome does, a decoder of its format and a resampler, loaded the first time one is needed; `computePeaks` reduces them to each slice's lowest and highest sample across all channels (so a take panned hard to one side still draws), and `normalizePeaks` scales them so the loudest sample reaches full height.

```tsx
import { computePeaks, normalizePeaks } from "@/lib/engine/analysis";
import { decodeAudioChannels } from "@/lib/engine/files";

const context = new AudioContext();
const channels = await decodeAudioChannels(context, await file.arrayBuffer());

const values = normalizePeaks(computePeaks(channels, 4096));
```

The second argument to `computePeaks` is a resolution, not a bar count: the canvas fits whatever you pass to its own width and to any `range`. Compute it once per file, with more slices than the widest view you expect will show (a few thousand covers a zoomed-in clip editor). For a simpler shape, `downsampleWaveform` and `normalizeWaveform` give one amplitude per slice instead.

</ForFrameworks>

## Showing part of the audio

`range` is the stretch of the audio to show, `[start, end]` in `duration` units. Everything follows it: the bars are drawn from that stretch of `values` alone, a press seeks inside it, the input's keys stay inside it, and regions and markers are placed across it.

```tsx
<Waveform
  aria-label="Clip"
  duration={source.duration}
  range={[clip.offset, clip.offset + clip.length]}
  values={source.peaks}
/>
```

When the position is outside the stretch, the root carries `data-outside` and the playhead is hidden, rather than pinned to an edge it hasn't reached. Past the largest canvas a browser will draw (16,384 pixels a side), the bitmap is drawn coarser rather than going blank.

</ForFrameworks>

<ForFrameworks only="react">

## Following playback

`value` re-renders React each time it changes, which is fine for a `timeupdate` event a few times a second. For a playhead that glides every animation frame, pass a `source`, an object in the shape of an external store:

```ts
interface WaveformSource {
  getSnapshot: () => number; // the position, in `duration` units
  subscribe: (listener: () => void) => () => void;
}
```

The waveform subscribes to it and moves the playhead, repaints the canvas and updates the input itself. While the pointer scrubs, the waveform follows the pointer and ignores the source until release; the same holds for a controlled `value` that updates late.

</ForFrameworks>

<ForFrameworks only="react">

## Regions and markers

Anything inside `Waveform` is laid over the canvas, on the same timeline. A region is `[start, end]` in `duration` units; drag its body to move it, and give it a handle per edge to resize it:

```tsx
const [loop, setLoop] = useState<readonly [number, number]>([48, 96]);

<Waveform aria-label="Track progress" duration={180} values={values}>
  <WaveformRegion onValueChange={setLoop} value={loop}>
    <WaveformRegionHandle aria-label="Loop start" edge="start" />
    <WaveformRegionHandle aria-label="Loop end" edge="end" />
  </WaveformRegion>
  <WaveformMarker value={124}>Chorus</WaveformMarker>
  <WaveformHover format={formatTime} />
</Waveform>
```

A press on a region never seeks the waveform underneath. Each handle is a slider of its own: it takes focus, and the arrow keys, <kbd>Page Up</kbd> / <kbd>Page Down</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> move its edge, which stops `minLength` short of the other one. Leave the handles out for a region that only moves, or pass `movable={false}` for one that only resizes.

</ForFrameworks>

## Live signals

A live waveform reads from a `source`, an object in the shape of an external store whose snapshot is the current levels, `0–1` each:

```ts
interface LevelsSource {
  getSnapshot: () => ArrayLike<number>;
  subscribe: (listener: () => void) => () => void;
}
```

The `use-audio-signal` hook (`npx shadcn@latest add @audio-ui/use-audio-signal`) reads two of them from an `AnalyserNode`, every animation frame and only while something is drawing them:

```tsx
const { level, bands, samples } = useAudioSignal(analyser, { bandCount: 32 });
```

- `level` is the loudest sample of the moment, as a single level. Draw it with `mode="scrolling"`: the waveform records it over time, the newest entering from the right, or from the middle outwards with `mirrored`. When the signal stops (pass `null` as the analyser to pause), the trace holds still.
- `bands` is the spectrum as log-spaced frequency bands, low to high. Draw it with a `BarVisualizer`, or a `LiveWaveform` in its default `mode="static"`: the bars stay in place and follow the bands, rising at once and falling smoothly.
- `samples` is the raw waveform of the moment, `-1` to `1`. Draw it with `shape="scope"`.

Any signal works. A source is an object with `getSnapshot()` and `subscribe(listener)`, which you push to yourself, from a WebSocket, a worklet or a test:

```tsx
let frame = new Float32Array(16);
const listeners = new Set<() => void>();

const levels = {
  getSnapshot: () => frame,
  subscribe(listener: () => void) {
    listeners.add(listener);
    return () => listeners.delete(listener);
  },
};

socket.onmessage = (event) => {
  frame = event.data;
  for (const listener of listeners) listener();
};
```

While its signal is audible, a live waveform carries `data-active`. `idle` picks what the bars do meanwhile (`"pulse"` breathes, `"wave"` ripples), and `loading` sweeps across them while a connection is on its way.

</ForFrameworks>

## Interaction

**Control**

- A press seeks, a drag scrubs, and the end of the gesture commits.
- Shift with a drag selects a stretch instead, reported to `onSelectionChange` and `onSelectionCommitted`. Without them a Shift drag is an ordinary seek.
- The arrows move by `step`, Shift with an arrow and Page Up and Page Down by `largeStep`, Home and End go to the ends.
- Nothing seeks while `disabled` or `loading`.

**Regions**

- Dragging a Region's body moves it, unless `movable` is false. Dragging a RegionHandle resizes that edge.
- On a handle's input, the arrows and Page keys move the edge and Home and End send it to its limit.
- A press on a region never reaches the Control underneath.

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `number` | `0` | The position, controlled or starting. |
| `source` | `{ getSnapshot, subscribe }` | | A live position, followed with no render. It takes precedence over `value`. |
| `duration` | `number` | `1` | The length of the audio, in the unit `value` is in. |
| `peaks` | `number[]` or `{ min, max }[]` | | The shape, at any resolution: a level per slice, or the lowest and highest sample of each. |
| `levels` | `{ getSnapshot, subscribe }` | | A live signal drawn instead of `peaks`. |
| `range` | `[start, end]` | the whole audio | The stretch shown. The position, seeking, hover, regions and markers follow it. |
| `step`, `largeStep` | `number` | a hundredth, a tenth of `duration` | The keys' steps. |
| `loading` | `boolean` | `false` | The audio is still on its way. Seeking waits. |
| `disabled` | `boolean` | `false` | Takes no gesture. |
| `name` | `string` | | The form field's name, carried by the seek input. |
| `onValueChange`, `onValueCommitted` | `(value, details) => void` | | A seek, and its end. |
| `onSelectionChange`, `onSelectionCommitted` | `(range, details) => void` | | A Shift drag. |
| `onRegionChange`, `onRegionCommitted` | `(region, details) => void` | | A region moved or resized, with `details.region` and `details.edge`. |

A Region takes `region` (its name), `value` or `defaultValue` (`[start, end]`), `minLength`, `movable` and `disabled`; a RegionHandle takes `edge` and the same `region`. The Canvas takes `variant`, `mode`, `barWidth`, `barGap`, `barRadius`, `gain`, `idle` and the rest of the painter's options, the Bars `count`, `gain`, `idle`, `minLevel` and `mirrored`. Colors come from `--waveform-color` and `--waveform-progress-color`.

### What a change reports

`details` carries:

- `reason`: `"press"`, `"drag"`, `"keyboard"` or `"input-change"`.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"programmatic"` or `"agent"`.
- `event` and `cancel()`: the DOM event behind it, and the refusal.
- For a region, `region` (its name) and `edge` (`"start"`, `"end"` or `"both"`).

In the web adapter, the seek is the `input` and `change` events, and the selection and the regions are `selectionchange`, `selectioncommit`, `regionchange` and `regioncommit`, each with a `detail` of the value and its reasons. `event.preventDefault()` refuses a change.

### States to style from

- `data-dragging` while a pointer scrubs or selects, `data-loading`, `data-disabled` on every part.
- `data-active` on the Root while a live signal is audible, and `data-outside` while the position is outside the stretch shown.
- `data-played` on the bars the position has passed, `data-index` on a bar, `data-region` and `data-edge` on a region and its handles.
