A linear control for continuous parameters such as volume, gain or a send level. The registry component is written on the `Fader` primitive of `@audio-ui/primitives`, which installs with it and adds size variants and thumb marks.

</ForFrameworks>

<ForFrameworks only="vue svelte web">

The fader's behavior is one description, `fader` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. Each framework renders it with a thin adapter that you copy into your project and own. A press on the track, the drag of the thumb, the wheel, the keys, the grid and the reset are the same in all four, and one suite of tests runs against each adapter.

</ForFrameworks>

## Overview

- **Input:** drag the thumb or press the track, or use the mouse wheel or the keyboard. `onValueCommitted` fires when the interaction ends.
- **Layout:** vertical by default, or horizontal, in `sm`, `default` and `lg` sizes.
- **Display:** a filled range and a thumb, with optional marks inside the thumb (`thumbMarks`).
- **Accessibility:** the thumb holds a native `<input type="range">` that carries the accessible name (`aria-label` or `aria-labelledby`), the value text (formatted with `format`) and the form value (`name`).

## Usage

<ForFrameworks only="react">

```tsx
import { Fader } from "@/components/audio-ui/fader";
```

**Uncontrolled:** set only the initial value.

```tsx
<Fader defaultValue={0} max={6} min={-60} step={1} />
```

**Controlled:** drive the value from state.

```tsx
const [gain, setGain] = useState(0);

<Fader
  max={6}
  min={-60}
  onValueChange={setGain}
  onValueCommitted={(value, details) => console.log("Committed:", value, details.reason)}
  step={1}
  value={gain}
/>
```

</ForFrameworks>

The parts are the same everywhere: a Root that owns the value, a Control that takes the pointer and the wheel, a Track and an Indicator that draw the travel and the fill, a Thumb that holds the focusable input, optional Marks along the track, and a Value for the text. A part takes the classes and attributes of its element, and the state attributes `data-disabled`, `data-dragging` and `data-orientation` to style from.

The Track, the Indicator, the Thumb and the Marks are positioned for you, from the bottom of a vertical fader and from the start edge of a horizontal one. Give the Track its length and the Control its size.

## Interaction

### Pointer

<KeyTable title="Behavior">
<KeyRow gesture={"Track click / drag"}>Click or drag on the track to set the value from the pointer position.</KeyRow>
<KeyRow gesture={"Thumb drag"}>Dragging the thumb changes the value continuously, within `min…max`.</KeyRow>
<KeyRow gesture={"Commit event"}>`onValueCommitted` fires when an interaction ends with a new value.</KeyRow>
<KeyRow gesture={"Lagging value"}>While dragging, the thumb follows the pointer even if a controlled `value` updates late; it returns to `value` on release. Reject a value with `eventDetails.cancel()`.</KeyRow>
</KeyTable>

### Keyboard

On the focused thumb:

<KeyTable title="Keys">
<KeyRow gesture={"`ArrowUp` / `ArrowRight`"}>Increase by `step`</KeyRow>
<KeyRow gesture={"`ArrowDown` / `ArrowLeft`"}>Decrease by `step`</KeyRow>
<KeyRow gesture={"`PageUp` / `Shift` + `ArrowUp`"}>Increase by `largeStep` (default `10`)</KeyRow>
<KeyRow gesture={"`PageDown` / `Shift` + `ArrowDown`"}>Decrease by `largeStep` (default `10`)</KeyRow>
<KeyRow gesture={"`Home`"}>Set to `min`</KeyRow>
<KeyRow gesture={"`End`"}>Set to `max`</KeyRow>
</KeyTable>

### Wheel

The mouse wheel over the fader moves the value by `step` and reports `eventDetails.reason === "wheel"`.

## API reference

<ForFrameworks only="react">

### Registry component

`Fader` accepts style props (`size`, `thumbMarks`, `className`) plus the props of the `Fader` primitive's Root (`name`, `form`, `format`, `locale`, `largeStep`, `render`, …). The primitive's `Fader.Mark` places a graduation at a `value` along the track, with `data-active` once the value has reached it, to build your own ruler. `aria-label`, `aria-labelledby`, and `aria-describedby` are forwarded to the thumb's input.

Additional valid HTML attributes passed to `Fader.Root` are forwarded.

A vertical fader takes the height it is given, and never less than `--fader-min-height` (10rem by default). Set it lower where room is short, such as a mixer on a small screen: `[--fader-min-height:5rem]` on a parent.

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `number` | the midpoint | The controlled value, or the starting one. `defaultValue` is also where a reset returns. |
| `min`, `max`, `step` | `number` | `-60`, `6`, `1` | The range, in dB for an audio fader, and the grid the value snaps to. |
| `largeStep` | `number` | `10` | What Page Up, Page Down and Shift with an arrow move by. |
| `anchor` | `number` | `min` | Where the Indicator's fill starts, like `0` on a pan from -1 to 1. |
| `orientation` | `"vertical"` or `"horizontal"` | `"vertical"` | Which way the travel runs. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | | The Value's text and the input's `aria-valuetext`. |
| `disabled` | `boolean` | `false` | Takes no key, wheel or press. |
| `name` | `string` | | The form field's name, carried by the input. |
| `onValueChange` | `(value, details) => void` | | Every change, which `details.cancel()` refuses. |
| `onValueCommitted` | `(value, details) => void` | | The end of a gesture. |

The Mark takes a `value` and carries `data-active` while the value has reached it from the anchor. The Thumb takes `getAriaValueText(formatted, value, index)` to announce the value in your own words, like `"-6 dB"`.

### What a change reports

`details` carries what moved the value and how:

- `reason`: `"drag"`, `"track-press"`, `"keyboard"`, `"wheel"`, `"input-change"` (a typed value) or `"reset"`.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"programmatic"` or `"agent"`, for analytics and for telling a person from an agent. It is never a reason to behave differently.
- `event`: the DOM event behind it, when there is one.
- `cancel()`: refuses the change. A controlled fader keeps the value you give it.

While a pointer drags the thumb, it follows the pointer even if a controlled `value` lags behind, as with a seek bar driven by playback time.

In the web adapter, `onValueChange` is an `input` event and `onValueCommitted` a `change` event, both with `detail: { value, reason, source }`, and `event.preventDefault()` refuses a change.

## For an agent

The fader declares one action, `setValue`, and the name on its Thumb is what an agent finds it by. The bridge of the framework you use (`createAgent` in `@ui-sdk/<framework>/agent`) reads its value and range, sets it with the source `"agent"`, and the same `onValueChange` hears it, so an app can refuse a value as it would a person's.
