<ForFrameworks only="vue svelte web">

The XY pad's behavior is one file, the primitive, written on the UI SDK kernel and copied into your project. Its value is a point, `{ x, y }`, two parameters moved at once. Each framework renders it with a thin adapter that you also own. The press, the drag, the wheel, the keys, the grid and the reset are the same in all four, and one suite of tests runs against each adapter.

</ForFrameworks>

## Overview

- **Input:** press or drag on the pad, or use the mouse wheel, a trackpad or the keyboard, on both axes.
- **Axes:** X and Y have their own range and step (`minX`, `maxX`, `stepX`; `minY`, `maxY`, `stepY`).
- **Display:** grid lines, a crosshair, a cursor and an optional value display. The position is exposed as the CSS variables `--xy-pad-x` (from the left) and `--xy-pad-y` (from the top).
- **Accessibility:** the cursor holds one native `<input type="range">` per axis. Both carry the accessible name (`aria-label` becomes "… X" and "… Y", or set each with `getAriaLabel` on the primitive's `Thumb`). The X input takes focus, and the arrow keys move both axes.

## Usage

<ForFrameworks only="react">

```tsx
import { XYPad } from "@/components/audio-ui/xypad";
```

**Uncontrolled:** set only the initial value.

```tsx
<XYPad
  defaultValue={{ x: 0, y: 0 }}
  maxX={100}
  maxY={1}
  minX={-100}
  minY={-1}
  stepX={1}
  stepY={0.01}
/>
```

**Controlled:** drive the value from state.

```tsx
const [position, setPosition] = useState({ x: 50, y: 50 });

<XYPad
  maxX={100}
  maxY={100}
  minX={0}
  minY={0}
  onValueChange={setPosition}
  onValueCommitted={(value, details) => console.log("Committed:", value, details.reason)}
  value={position}
/>
```

### Two inputs, one name

The Thumb holds a native `<input type="range">` for each axis. Both carry the name, which is the Thumb's `aria-label` followed by "X" or "Y" (`getAriaLabel(axis)` on the Thumb says it in your own words), and the form names `<name>.x` and `<name>.y`. Only the X input is in the tab order, and the arrow keys move both axes from it.

## Interaction

### Pointer

<KeyTable title="Behavior">
<KeyRow gesture={"Press / drag on pad"}>A press jumps the value to the pointer; a drag follows it. Reported as `eventDetails.reason` `"press"` then `"drag"`.</KeyRow>
<KeyRow gesture={"Clamping"}>Values always clamp to the configured axis ranges and snap to `stepX` / `stepY`.</KeyRow>
<KeyRow gesture={"Commit event"}>`onValueCommitted` fires when a gesture that changed the value ends.</KeyRow>
<KeyRow gesture={"Lagging value"}>While dragging, the cursor follows the pointer even if a controlled `value` updates late. Reject a value with `eventDetails.cancel()`.</KeyRow>
</KeyTable>

### Keyboard

On the focused pad:

<KeyTable title="Keys">
<KeyRow gesture={"`ArrowLeft` / `ArrowRight`"}>Decrease / increase X by `stepX`</KeyRow>
<KeyRow gesture={"`ArrowUp` / `ArrowDown`"}>Increase / decrease Y by `stepY`</KeyRow>
<KeyRow gesture={"`Shift` + arrow"}>Move by 10 steps</KeyRow>
<KeyRow gesture={"`PageUp` / `PageDown`"}>Increase / decrease Y by `stepY × 10`</KeyRow>
<KeyRow gesture={"`Home` / `End`"}>X to `minX` / `maxX`</KeyRow>
</KeyTable>

### Wheel

Wheel and trackpad input over the pad moves the point by the scrolled distance: scrolling up raises Y, scrolling right raises X. Reported as `eventDetails.reason === "wheel"`.

The `XYPad` primitive that installs with it exposes `XYPad.Root`, `XYPad.Control` (the pad surface), `XYPad.Thumb` (positioned at the value, holds the axis inputs), `XYPad.Value` (formatted `<output>`), and `XYPad.Label`. Every part accepts a `render` prop, `className` / `style` as functions of state, and exposes `data-disabled` / `data-dragging`. Draw grids and crosshairs with your own elements and the `--xy-pad-x` / `--xy-pad-y` variables.

### Options

Set on the Root, as props (an attribute in kebab case in the web adapter).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `{ x, y }` | the center | The controlled point, or the starting one. `defaultValue` is also where a reset returns. |
| `minX`, `maxX`, `minY`, `maxY` | `number` | `0`, `100` | The range of each axis. |
| `stepX`, `stepY` | `number` | `1` | The grid each axis snaps to. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | | How each axis is written, for the Value and the inputs' `aria-valuetext`. |
| `disabled` | `boolean` | `false` | Takes no key, wheel or press. |
| `name` | `string` | | The form field's name. |
| `onValueChange` | `(point, details) => void` | | Every change, which `details.cancel()` refuses. |
| `onValueCommitted` | `(point, details) => void` | | The end of a gesture. |

The Value shows both axes as one text, with the separator of the locale. Its content can read `formatted.x`, `formatted.y` and `value` from the state.

### What a change reports

`details` carries what moved the point and how:

- `reason`: `"press"`, `"drag"`, `"keyboard"`, `"wheel"`, `"input-change"` (a typed value) or `"reset"`.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"programmatic"` or `"agent"`.
- `event`: the DOM event behind it, when there is one.
- `cancel()`: refuses the change. A controlled pad keeps the point you give it.

In the web adapter, `onValueChange` is an `input` event and `onValueCommitted` a `change` event, both with `detail: { value, reason, source }`, where `value` is the point, and `event.preventDefault()` refuses a change.

## For an agent

The pad declares one action, `setValue(x, y)`, and the name on its Thumb is what an agent finds it by. The bridge of the framework you use (`createAgent` in `@ui-sdk/<framework>/agent`) sets the point with the source `"agent"`. Each axis is a change of its own, so `onValueChange` hears two, and an app can refuse either.
