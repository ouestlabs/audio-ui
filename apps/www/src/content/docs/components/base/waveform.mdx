Waveform for scrubbing through audio: bars drawn on a canvas that fill in as the position advances. The registry component wraps the `Waveform` primitive from `@audio-ui/react`; the primitive has no opinion on where the amplitudes came from (real decoded PCM samples, a placeholder curve, anything), the same way `PianoRoll` has no opinion on where its notes came from.

## Overview

- **Value model:** `value` is the playback position, from `0` to `duration` (default `1`, so a plain `0–1` fraction; pass the track's length in seconds to work in seconds). The primitive only owns the seek position, never the audio itself: wire `onValueChange` to your own `<audio>` element.
- **Bar data:** pass `values` (raw `0–1` amplitudes) at any resolution. The canvas draws as many fixed-width bars as fit its real width and keeps the loudest amplitude in each bar's slice, so the waveform keeps its detail from a chat bubble to a full-width editor. Bars are laid out on the screen's physical pixels, so their edges stay sharp at any pixel density or zoom level. See [Feeding real audio](#feeding-real-audio).
- **Live position:** for a playhead that moves every frame, pass a [`source`](#following-playback) instead of `value`: the waveform follows it straight in the DOM, with no React render.
- **Variants:** `variant="default"` renders just the recolored bars. `variant="playhead"` additionally renders a playhead line and a handle at the current position.
- **Accessibility:** the waveform holds a native `<input type="range">` in both variants: it takes focus, carries `aria-label`, announces the played share (or whatever `getAriaValueText` returns, e.g. a time), and supports arrow keys / <kbd>Home</kbd> / <kbd>End</kbd> / <kbd>Page Up</kbd> / <kbd>Page Down</kbd>.

## Usage

```tsx
import { Waveform } from "@/components/audio/elements/waveform";
```

**Bars only:**

```tsx
<Waveform aria-label="Track progress" value={progress} values={values} />
```

**With a playhead line and handle, in seconds:**

```tsx
<Waveform
  aria-label="Track progress"
  duration={audio.duration}
  onValueChange={(seconds) => {
    audio.currentTime = seconds;
  }}
  value={currentTime}
  values={values}
  variant="playhead"
/>
```

## Feeding real audio

`values` is a plain prop: the component doesn't decode anything on its own. The `waveform-dsp` lib (`npx shadcn@latest add @audio/waveform-dsp`) turns a real audio file into `values`: `decodeAudioSamples` reads PCM samples out of an `AudioContext`, `downsampleWaveform` reduces them to a manageable number of amplitudes (keeping each block's peak, not its average, so transients stay sharp), and `normalizeWaveform` scales them so the loudest reaches full height.

```tsx
import {
  decodeAudioSamples,
  downsampleWaveform,
  normalizeWaveform,
} from "@/lib/waveform-dsp";

const context = new AudioContext();
const buffer = await file.arrayBuffer();
const samples = await decodeAudioSamples(context, buffer);

const values = normalizeWaveform(downsampleWaveform(samples, 1000));
```

The second argument to `downsampleWaveform` is a resolution, not a bar count: the canvas fits whatever you pass to its own width. Give it more values than the widest bar count you expect (a thousand is plenty) rather than tuning it per layout.

## Following playback

`value` re-renders React each time it changes, which is fine for a `timeupdate` event a few times a second. For a playhead that glides every animation frame, pass a `source`, an object in the shape of an external store:

```ts
interface WaveformSource {
  getSnapshot: () => number; // the position, in `duration` units
  subscribe: (listener: () => void) => () => void;
}
```

The waveform subscribes to it and moves the playhead, repaints the canvas and updates the input itself. While the pointer scrubs, the waveform follows the pointer and ignores the source until release; the same holds for a controlled `value` that updates late.

## Theming

The canvas reads its colors from CSS, and repaints when the theme changes:

| Variable | Default | Purpose |
| -------- | ------- | ------- |
| `--waveform-color` | text color | Bars ahead of the position. |
| `--waveform-progress-color` | `--waveform-color` | Bars behind the position. |
| `--waveform-bar-radius` | `0px` | Bar corner radius (any CSS length). |

The position itself is exposed as `--waveform-position` (a percentage) on the root.

## API reference

`Waveform` accepts `values`, `variant`, `getAriaValueText` and `className`, plus primitive props from `WaveformPrimitive.Root.Props`. `aria-label`, `aria-labelledby`, and `aria-describedby` are forwarded to the waveform's input.

### Value and state

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `values` | `ArrayLike<number>` | - | Raw `0–1` amplitudes, at any resolution. |
| `value` | `number` | - | Controlled position, from `0` to `duration`. |
| `defaultValue` | `number` | `0` | Uncontrolled starting position. |
| `source` | `WaveformSource` | - | A live position followed outside React; takes precedence over `value`. |
| `duration` | `number` | `1` | Length of the audio, in the unit `value` is in. |
| `step` | `number` | `duration / 100` | Arrow key step. |
| `largeStep` | `number` | `duration / 10` | Step for `PageUp` / `PageDown` and `Shift` + arrows. |
| `disabled` | `boolean` | `false` | Disables pointer and keyboard interaction. |
| `onValueChange` | `(value: number, eventDetails) => void` | - | Fires while seeking. `eventDetails.reason` is `"press"`, `"drag"`, `"keyboard"`, or `"input-change"`; call `eventDetails.cancel()` to reject it. |
| `onValueCommitted` | `(value: number, eventDetails) => void` | - | Fires when a seek that moved the position ends. |
| `getAriaValueText` | `(value: number, duration: number) => string` | played share | How the position is announced, e.g. `"0:12 of 1:42"`. |

### Layout and display

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `variant` | `"default" \| "playhead"` | `"default"` | `playhead` adds a playhead line and a handle. |
| `className` | `string` | - | Classes for the waveform surface. |

### Primitive parts

`@audio-ui/react/waveform` exposes `Waveform.Root`, `Waveform.Control` (the seekable surface, holds the input), `Waveform.Canvas` (`barWidth`, `barGap`, `barRadius`, `variant: "mirror" | "bars"`), `Waveform.Playhead`, `Waveform.Thumb` and `Waveform.Hover` (shown at the hovered position; its children receive that position, to print a time). Every part accepts a `render` prop and `className` / `style` as functions of state, and exposes `data-disabled` / `data-dragging`.
