One family for drawing audio. `Waveform` shows a whole file and lets you scrub through it; `LiveWaveform` follows a signal as it happens; `BarVisualizer` turns that signal into a handful of bars you style in CSS. All three wrap the `Waveform` primitive from `@audio-ui/react`, which has no opinion on where the audio came from: decoded PCM samples, a microphone, a stream from your server.

## Overview

- **Two kinds of data:** a file's shape is known upfront, so `Waveform` takes `values` (raw `0–1` amplitudes, at any resolution). A live signal isn't, so `LiveWaveform` and `BarVisualizer` take a [`source`](#live-signals) they follow outside React.
- **Value model:** `value` is the playback position, from `0` to `duration` (default `1`, so a plain `0–1` fraction; pass the track's length in seconds to work in seconds). The primitive only owns the seek position, never the audio itself: wire `onValueChange` to your own `<audio>` element.
- **The real shape:** give `values` each slice's lowest and highest sample (`{ min, max }`) and the waveform is drawn lopsided where the audio is, as a DAW draws it; plain amplitudes (`0–1`) draw it the same above and below the middle.
- **Part of the audio:** `range` shows just a stretch of it (a clip's window onto its source, a zoomed view), and the playhead, seeking, hover, regions and markers all follow that stretch. See [Showing part of the audio](#showing-part-of-the-audio).
- **Sharp at any size:** the canvas draws as many bars as fit its real width and keeps the loudest of each bar's slice, so the waveform keeps its detail from a chat bubble to a full-width editor. Bars are laid out on the screen's physical pixels, so their edges stay sharp at any pixel density or zoom level. See [Feeding real audio](#feeding-real-audio).
- **Shapes:** `shape="mirror"` (the default) centers the bars, `"bars"` stands them on the baseline and `"line"` joins the levels into one continuous shape. A live waveform can also be a `"scope"`: raw samples traced as a single line, like an oscilloscope.
- **On the timeline:** [`WaveformRegion`](#regions-and-markers) is a stretch you can move and resize, such as a loop; `WaveformMarker` is a labelled point; `WaveformHover` follows the pointer and prints the hovered time.
- **Nothing wasted:** every moving part is painted outside React and only when something changed. A waveform that is off screen, or has come to rest, costs no frames. With reduced motion requested, live waveforms repaint a few times a second, without smoothing or idle animation.
- **Accessibility:** the seekable waveform holds a native `<input type="range">`: it takes focus, carries `aria-label`, announces the played share (or whatever `getAriaValueText` returns, e.g. a time), and supports arrow keys / <kbd>Home</kbd> / <kbd>End</kbd> / <kbd>Page Up</kbd> / <kbd>Page Down</kbd>. Each region handle holds one too. Live waveforms are images: give them an `aria-label`.

## Usage

```tsx
import {
  BarVisualizer,
  LiveWaveform,
  Waveform,
  WaveformHover,
  WaveformMarker,
  WaveformRegion,
  WaveformRegionHandle,
} from "@/components/audio/elements/waveform";
```

**A file, in seconds, with a playhead line and handle:**

```tsx
<Waveform
  aria-label="Track progress"
  duration={audio.duration}
  onValueChange={(seconds) => {
    audio.currentTime = seconds;
  }}
  value={currentTime}
  values={values}
  variant="playhead"
/>
```

**A microphone, scrolling as it comes in:**

```tsx
const { level } = useAudioSignal(analyser);

<LiveWaveform aria-label="Microphone input" mode="scrolling" source={level} />;
```

**A voice, as bars:**

```tsx
const { bands } = useAudioSignal(analyser);

<BarVisualizer aria-label="Agent speaking" mirrored source={bands} />;
```

## Feeding real audio

`values` is a plain prop: the component doesn't decode anything on its own. The `waveform-dsp` lib (`npx shadcn@latest add @audio/waveform-dsp`) turns a real audio file into `values`: `decodeAudioChannels` reads every channel's PCM samples out of an `AudioContext`, `computePeaks` reduces them to each slice's lowest and highest sample across all channels (so a take panned hard to one side still draws), and `normalizePeaks` scales them so the loudest sample reaches full height.

```tsx
import {
  computePeaks,
  decodeAudioChannels,
  normalizePeaks,
} from "@/lib/waveform-dsp";

const context = new AudioContext();
const channels = await decodeAudioChannels(context, await file.arrayBuffer());

const values = normalizePeaks(computePeaks(channels, 4096));
```

The second argument to `computePeaks` is a resolution, not a bar count: the canvas fits whatever you pass to its own width and to any `range`. Compute it once per file, with more slices than the widest view you expect will show (a few thousand covers a zoomed-in clip editor). For a simpler shape, `downsampleWaveform` and `normalizeWaveform` give one amplitude per slice instead.

## Showing part of the audio

`range` is the stretch of the audio to show, `[start, end]` in `duration` units. Everything follows it: the bars are drawn from that stretch of `values` alone, a press seeks inside it, the input's keys stay inside it, and regions and markers are placed across it.

```tsx
<Waveform
  aria-label="Clip"
  duration={source.duration}
  range={[clip.offset, clip.offset + clip.length]}
  values={source.peaks}
/>
```

When the position is outside the stretch, the root carries `data-outside` and the playhead is hidden, rather than pinned to an edge it hasn't reached. Past the largest canvas a browser will draw (16,384 pixels a side), the bitmap is drawn coarser rather than going blank.

## Following playback

`value` re-renders React each time it changes, which is fine for a `timeupdate` event a few times a second. For a playhead that glides every animation frame, pass a `source`, an object in the shape of an external store:

```ts
interface WaveformSource {
  getSnapshot: () => number; // the position, in `duration` units
  subscribe: (listener: () => void) => () => void;
}
```

The waveform subscribes to it and moves the playhead, repaints the canvas and updates the input itself. While the pointer scrubs, the waveform follows the pointer and ignores the source until release; the same holds for a controlled `value` that updates late.

## Regions and markers

Anything inside `Waveform` is laid over the canvas, on the same timeline. A region is `[start, end]` in `duration` units; drag its body to move it, and give it a handle per edge to resize it:

```tsx
const [loop, setLoop] = useState<readonly [number, number]>([48, 96]);

<Waveform aria-label="Track progress" duration={180} values={values}>
  <WaveformRegion onValueChange={setLoop} value={loop}>
    <WaveformRegionHandle aria-label="Loop start" edge="start" />
    <WaveformRegionHandle aria-label="Loop end" edge="end" />
  </WaveformRegion>
  <WaveformMarker value={124}>Chorus</WaveformMarker>
  <WaveformHover format={formatTime} />
</Waveform>
```

A press on a region never seeks the waveform underneath. Each handle is a slider of its own: it takes focus, and the arrow keys, <kbd>Page Up</kbd> / <kbd>Page Down</kbd>, <kbd>Home</kbd> and <kbd>End</kbd> move its edge, which stops `minLength` short of the other one. Leave the handles out for a region that only moves, or pass `movable={false}` for one that only resizes.

## Live signals

A live waveform reads from a `source`, an object in the shape of an external store whose snapshot is the current levels, `0–1` each:

```ts
interface LevelsSource {
  getSnapshot: () => ArrayLike<number>;
  subscribe: (listener: () => void) => () => void;
}
```

The `use-audio-signal` hook (`npx shadcn@latest add @audio/use-audio-signal`) reads two of them from an `AnalyserNode`, every animation frame and only while something is drawing them:

```tsx
const { level, bands, samples } = useAudioSignal(analyser, { bandCount: 32 });
```

- `level` is the loudest sample of the moment, as a single level. Draw it with `mode="scrolling"`: the waveform records it over time, the newest entering from the right, or from the middle outwards with `mirrored`. When the signal stops (pass `null` as the analyser to pause), the trace holds still.
- `bands` is the spectrum as log-spaced frequency bands, low to high. Draw it with a `BarVisualizer`, or a `LiveWaveform` in its default `mode="static"`: the bars stay in place and follow the bands, rising at once and falling smoothly.
- `samples` is the raw waveform of the moment, `-1` to `1`. Draw it with `shape="scope"`.

Any signal will do. `createSource` from `@audio-ui/react` makes a source you push to yourself, from a WebSocket, a worklet or a test:

```tsx
import { createSource } from "@audio-ui/react";

const levels = createSource(new Float32Array(16));

socket.onmessage = (event) => levels.set(event.data);
```

While its signal is audible, a live waveform carries `data-active`. `idle` picks what the bars do meanwhile (`"pulse"` breathes, `"wave"` ripples), and `loading` sweeps across them while a connection is on its way.

## Theming

Colors come from CSS, and the canvas repaints when the theme changes:

| Variable | Default | Purpose |
| -------- | ------- | ------- |
| `--waveform-color` | text color | Bars ahead of the position, and every bar of a live waveform. |
| `--waveform-progress-color` | `--waveform-color` | Bars behind the position. |
| `--waveform-bar-radius` | `0px` | Bar corner radius on the canvas (any CSS length). |
| `--waveform-position` | - | Set on the root: the playback position, as a percentage. |
| `--waveform-level` | - | Set on each bar of a `BarVisualizer`: its level, `0–1`. |

The bars of a `BarVisualizer` are plain elements: restyle them with `.cn-bar-visualizer-bar`. Those the playback position has passed carry `data-played`.

## API reference

### Root

Groups the parts of a waveform and owns what they show: the audio's shape (`peaks`, known upfront, or a live `levels` signal) and, for a seekable one, the playback position in `duration` units. The position comes from `value`, or from a live `source` that the waveform follows straight in the DOM without re-rendering React; it is exposed as the `--waveform-position` CSS variable (a percentage). While a live signal is audible the element carries `data-active`. Renders a `<div>` element.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `defaultValue` | `number` | `0` | Uncontrolled starting position. |
| `disabled` | `boolean` |  |  |
| `duration` | `number` | `1` | Length of the audio, in the unit `value` is in (typically seconds). |
| `largeStep` | `number` |  | Step for Page Up/Page Down and Shift + arrow keys. Defaults to a tenth of `duration`. |
| `levels` | `Levels` |  | A live signal drawn outside React, in place of `peaks`: a microphone, an analyser, a stream. |
| `loading` | `boolean` | `false` | Whether the audio is still on its way. Seeking waits, and the bars sweep. |
| `onValueChange` | `(value: number, eventDetails: ChangeEventDetails) => void` |  | Fires while seeking: press, drag, keyboard and input changes. |
| `onValueCommitted` | `( value: number, eventDetails: CommitEventDetails ) => void` |  | Fires when a seek that moved the position ends. |
| `peaks` | `WaveformPeaks` |  | The audio's shape, at any resolution: a level per slice (0…1), or the lowest and highest sample of each (`{ min, max }`, -1…1), which draws the waveform lopsided where the audio is. The parts fit it to their size. |
| `range` | `readonly [number, number]` |  | The stretch of the audio to show, `[start, end]` in `duration` units: a clip's window onto its source, a zoomed view. ### Control

| `gain` | `number` | `1` | Visual gain applied to the levels before they are drawn. |

### Canvas

Draws the waveform on a canvas, laid out on the device pixel grid: as many bars as fit its width, every edge on a physical pixel, so it stays sharp at any pixel density and zoom level. It paints only when something changed, and not at all while it is off screen. With `peaks`, the played part is drawn in one color and the rest in another. With a live `levels` signal, `mode` picks between the current levels across the width and a scrolling record of the loudest one. The `scope` variant takes raw samples instead of levels, and traces them as they are. Colors come from CSS: `--waveform-color` and `--waveform-progress-color` (both default to the text color). The bar corner radius is `barRadius`, or the `--waveform-bar-radius` CSS length. Renders a `<canvas>` element.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `barGap` | `number` | `1` | Space between bars, in CSS pixels, snapped to whole device pixels. |
| `barRadius` | `number` |  | Bar corner radius, in CSS pixels. Defaults to the `--waveform-bar-radius` CSS length. |
| `barWidth` | `number` | `2` | Bar width, in CSS pixels, snapped to whole device pixels. |
| `gain` | `number` | `1` | Visual gain applied to the levels before they are drawn. |
| `idle` | `WaveformIdle` | `"none"` | What the bars do while there is no signal, outside the scrolling mode. |
| `lineWidth` | `number` | `1.5` | Thickness of the `scope` trace, in CSS pixels. |
| `minBarHeight` | `number` | `2` | Shortest bar, in CSS pixels: silence still draws a sliver, so the timeline stays readable. |
| `mirrored` | `boolean` | `false` | Makes the drawing symmetric around the middle: the first level sits in the center, or, when scrolling, the newest one, with older ones moving out on both sides. |
| `mode` | `"scrolling" \| "static"` | `"static"` | How a live `levels` signal is drawn: `static` spreads the current levels across the width; `scrolling` records the loudest one over time, the newest entering from the right. |
| `scrollSpeed` | `number` | `60` | How fast the scrolling mode moves, in CSS pixels per second. |
| `variant` | `WaveformVariant` | `"mirror"` | `mirror` centers the bars on the middle line, `bars` stands them on the baseline, and `line` joins the levels into one continuous, centered shape. `scope` traces raw samples, -1…1, as a single line. |

| Data attribute | Description |
| --- | --- |
| `data-disabled` | Present when disabled. |
| `data-dragging` | Whether a pointer is scrubbing the waveform. |
| `data-loading` | Whether the audio is still on its way: there is nothing to seek yet. |

| `mode` | `"static" \| "scrolling"` | `"static"` | `static` spreads the current levels across the width; `scrolling` records the loudest one over time. |
| `scrollSpeed` | `number` | `60` | How fast `scrolling` moves, in pixels per second. |
| `shape` | `"mirror" \| "bars" \| "line" \| "scope"` | `"mirror"` | How the signal is drawn. `scope` traces raw samples instead of levels. |
| `gain` | `number` | `1` | Visual gain applied to the levels. |
| `mirrored` | `boolean` | `false` | Makes the drawing symmetric: the first level in the center, or, when scrolling, the newest one, with older ones moving out on both sides. |
| `idle` | `"none" \| "pulse" \| "wave"` | `"none"` | In `static` mode, what the bars do while there is no signal. |
| `loading` | `boolean` | `false` | Sweeps across the bars while the signal is on its way. |

#### BarVisualizer

| Prop | Type | Default | Description |
| ---- | ---- | ------- | ----------- |
| `source` | `LevelsSource \| null` | - | The live signal. |
| `count` | `number` | `24` | How many bars; the levels are fitted to them. |
| `mirrored` | `boolean` | `false` | Mirrors the levels around the middle bar, the lowest band in the center. |
| `minLevel` | `number` | `0.08` | Resting level: silent bars keep this much of their size. |
| `gain` | `number` | `1` | Visual gain applied to the levels. |
| `idle` | `"none" \| "pulse" \| "wave"` | `"none"` | What the bars do while there is no signal. |
| `loading` | `boolean` | `false` | Sweeps across the bars while the signal is on its way. |
| `align` | `"start" \| "center" \| "end"` | `"center"` | Where the bars grow from. |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | `vertical` stacks the bars and grows them sideways. |



`@audio-ui/react/waveform` exposes the parts these components are built from:

| Part | Role |
| ---- | ---- |
| `Waveform.Root` | Owns the data (`peaks`, or a live `levels` source) and the position (`value`, `source`, `duration`). Carries `data-active` while a live signal is audible. |
| `Waveform.Control` | The seekable surface; holds the input. Leave it out for a waveform that is only shown. |
| `Waveform.Canvas` | Draws on a canvas: `variant`, `mode`, `scrollSpeed`, `barWidth`, `barGap`, `barRadius`, `minBarHeight`, `lineWidth`, `gain`, `mirrored`, `idle`. |
| `Waveform.Bars`, `Waveform.Bar` | Draws as elements: `count`, `minLevel`, `gain`, `mirrored`, `idle`. Each bar gets `--waveform-level`, `data-index` and `data-played`. |
| `Waveform.Region`, `Waveform.RegionHandle` | A stretch of the timeline, and the handle of one of its edges. |
| `Waveform.Marker` | A point on the timeline. |
| `Waveform.Playhead`, `Waveform.Thumb` | Follow the playback position. |
| `Waveform.Hover` | Shown at the hovered position; its children receive that position. |

Every part accepts a `render` prop and `className` / `style` as functions of state, and exposes that state as data attributes such as `data-disabled`, `data-dragging` and `data-loading`.
