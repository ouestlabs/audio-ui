The fader's behavior is one description, `fader` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. Each framework renders it with a thin adapter that you copy into your project and own. A press on the track, the drag of the thumb, the wheel, the keys, the grid and the reset are the same in all four, and one suite of tests runs against each adapter.

The primitives are built on the [UI SDK](https://ui-sdk.dev) kernel, in beta. `@audio-ui/primitives` is on npm, and each item below installs it with the adapter. The [knob](/docs/knob-ui-sdk) is built the same way.

## Usage

The parts are the same everywhere: a Root that owns the value, a Control that takes the pointer and the wheel, a Track and an Indicator that draw the travel and the fill, a Thumb that holds the focusable input, optional Marks along the track, and a Value for the text. A part takes the classes and attributes of its element, and the state attributes `data-disabled`, `data-dragging` and `data-orientation` to style from.

The Track, the Indicator, the Thumb and the Marks are positioned for you, from the bottom of a vertical fader and from the start edge of a horizontal one. Give the Track its length and the Control its size.

## Interaction

- A press on the track jumps to the value under the pointer, and a press on the thumb drags from where it was taken.
- The mouse wheel steps the value. Arrows move one `step`, Shift with an arrow or Page Up and Page Down move `largeStep`, Home and End go to the ends.
- A double click, an Alt with a click, or Delete returns to `defaultValue`.
- A disabled fader takes none of these.

## Options

Set on the Root, as props (an attribute in kebab case on the custom element).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `number` | the midpoint | The controlled value, or the starting one. `defaultValue` is also where a reset returns. |
| `min`, `max`, `step` | `number` | `-60`, `6`, `1` | The range, in dB for an audio fader, and the grid the value snaps to. |
| `largeStep` | `number` | `10` | What Page Up, Page Down and Shift with an arrow move by. |
| `anchor` | `number` | `min` | Where the Indicator's fill starts, like `0` on a pan from -1 to 1. |
| `orientation` | `"vertical"` or `"horizontal"` | `"vertical"` | Which way the travel runs. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | | The Value's text and the input's `aria-valuetext`. |
| `disabled` | `boolean` | `false` | Takes no key, wheel or press. |
| `name` | `string` | | The form field's name, carried by the input. |
| `onValueChange` | `(value, details) => void` | | Every change, which `details.cancel()` refuses. |
| `onValueCommitted` | `(value, details) => void` | | The end of a gesture. |

The Mark takes a `value` and carries `data-active` while the value has reached it from the anchor. The Thumb takes `getAriaValueText(formatted, value, index)` to announce the value in your own words, like `"-6 dB"`.

## What a change reports

`details` carries what moved the value and how:

- `reason`: `"drag"`, `"track-press"`, `"keyboard"`, `"wheel"`, `"input-change"` (a typed value) or `"reset"`.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"programmatic"` or `"agent"`, for analytics and for telling a person from an agent. It is never a reason to behave differently.
- `event`: the DOM event behind it, when there is one.
- `cancel()`: refuses the change. A controlled fader keeps the value you give it.

While a pointer drags the thumb, it follows the pointer even if a controlled `value` lags behind, as with a seek bar driven by playback time.

On the custom element, `onValueChange` is an `input` event and `onValueCommitted` a `change` event, both with `detail: { value, reason, source }`, and `event.preventDefault()` refuses a change.

## For an agent

The fader declares one action, `setValue`, and the name on its Thumb is what an agent finds it by. The bridge of the framework you use (`createAgent` in `@ui-sdk/<framework>/agent`) reads its value and range, sets it with the source `"agent"`, and the same `onValueChange` hears it, so an app can refuse a value as it would a person's.
