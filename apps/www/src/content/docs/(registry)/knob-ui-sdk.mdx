The knob's behavior is one description, `knob` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. Each framework renders it with a thin adapter that you copy into your project and own: a few parts, about 120 to 150 lines. The drag, the wheel, the keys, the scale and the reset are the same in all four, and one suite of tests runs against each adapter.

The primitives are built on the [UI SDK](https://ui-sdk.dev) kernel, in beta. `@audio-ui/primitives` is not published yet: this page describes what the next release installs.

## Installation

Each framework has its own item, and its CLI puts the files where that framework keeps its components. The CLI also installs what they import.

## Usage

The parts are the same everywhere: a Root that owns the value, a Control that takes the pointer and the wheel, a Track and an Indicator that draw the arcs, a Thumb that holds the focusable input, and a Value for the text. A part takes the classes and attributes of its element, and a state attribute (`data-dragging`, `data-disabled`, `data-drag-mode`) on each part to style from.

## Options

Set on the Root, as props (an attribute in kebab case on the custom element).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `number` | the midpoint | The controlled value, or the starting one. `defaultValue` is also where a reset returns. |
| `min`, `max`, `step` | `number` | `0`, `100`, `1` | The range and the grid the value snaps to. |
| `largeStep` | `number` | | What Page Up, Page Down and Shift with an arrow move by. |
| `anchor` | `number` | | Where the Indicator's arc starts, like `0` for a pan. |
| `scale` | `"linear"`, `"log"` or `{ toPosition, toValue }` | `"linear"` | How the value maps onto the dial. |
| `dragMode` | `"circular"`, `"revolution"`, `"vertical"` | `"circular"` | How pointer travel turns into value. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | | The Value's text and the input's `aria-valuetext`. |
| `disabled` | `boolean` | `false` | Takes no key, wheel or drag. |
| `name` | `string` | | The form field's name, carried by the input. |
| `onValueChange` | `(value, details) => void` | | Every change, which `details.cancel()` refuses. |
| `onValueCommitted` | `(value, details) => void` | | The end of a gesture. |

## What a change reports

`details` carries what moved the value and how:

- `reason`: `"drag"`, `"wheel"`, `"keyboard"` or `"reset"`.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"`, `"programmatic"` or `"agent"`, for analytics and for telling a person from an agent. It is never a reason to behave differently.
- `event`: the DOM event behind it, when there is one.
- `cancel()`: refuses the change. A controlled knob keeps the value you give it.

On the custom element, `onValueChange` is an `input` event and `onValueCommitted` a `change` event, both with `detail: { value, reason, source }`, and `event.preventDefault()` refuses a change.

## For an agent

The knob declares one action, `setValue`, and the name on its Thumb is what an agent finds it by. The bridge of the framework you use (`createAgent` in `@ui-sdk/<framework>/agent`) reads its value and range, sets it with the source `"agent"`, and the same `onValueChange` hears it, so an app can refuse a value as it would a person's.

## Differences from the React knob of `@audio-ui/react`

The behavior is the same, and so are the `data-*` state attributes. These differ:

- Every part carries a `data-slot` attribute, such as `knob-thumb`.
- A change reports a `source`.
- The Mark part is in every framework, custom elements included.
- `Knob.Provider` gives its knobs a drag mode in React, Vue and Svelte; the custom elements have none.

## Package

`@audio-ui/primitives` holds the behavior (`@audio-ui/primitives/knob`) with `@ui-sdk/core` as a peer dependency, pinned to the beta the primitives are written for. The adapters are in the registry, not the package.
