The piano's behavior is one description, `piano` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. A key sounds while it is pressed, by pointer or from the keyboard, and dragging across the keys glides from one to the next. Each framework renders it with a thin adapter that you copy into your project and own, and one suite of tests runs against each adapter.

The primitives are built on the [UI SDK](https://ui-sdk.dev) kernel, in beta. `@audio-ui/primitives` is not published yet: this page describes what the next release installs. The [knob](/docs/knob-ui-sdk), the [fader](/docs/fader-ui-sdk), the [XY pad](/docs/xypad-ui-sdk), the [meter](/docs/meter-ui-sdk) and the [envelope](/docs/envelope-ui-sdk) are built the same way.

## Usage

A Root is the keyboard, and a Key is one key, a `<button>` placed along it for its `pitch` and named by its note, such as "C4". A Label inside a Key writes that name for you to style. You write a Key for each pitch: the Root's content can read the state, whose `pitches` lists them lowest first, so the keys follow `minPitch`, `maxPitch` and `pitches`. That is a function in React, the default slot in Vue and a snippet in Svelte.

**Give the Root its size.** The keys are placed with percentages, so a Root with no height or width has nothing to place them in.

            pitch={pitch}

On a custom element, the keyboard makes a key for each pitch, each a wrapper around a `<button>`. To style or fill them yourself, write the `audio-ui-piano-key` elements with a `pitch` and a button inside: the keyboard then leaves them as they are, and an `audio-ui-piano-label` inside a button gets its note.

## Interaction

- A press strikes the key under the pointer, harder toward its free end, from 0.25 to 1. Black keys sit on top of the white ones and are tried first.
- Dragging across the keys glides: the key left is released with the reason `"glide"`, and the one entered sounds. Each pointer holds its own key, so chords can be played on a touch screen.
- Enter and Space play a key at 0.8 until the key is released or it loses focus.
- The keys are one tab stop, which starts on middle C. The arrows walk the keys, Shift with an arrow moves an octave, Page Up and Page Down move an octave, Home and End go to the ends.

## Options

Set on the Root, as props (an attribute in kebab case on the custom element).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `minPitch`, `maxPitch` | `number` | `48`, `72` | The lowest and highest MIDI pitch, inclusive: 60 is middle C. |
| `pitches` | `number[]` | | Only these pitches get keys, instead of `minPitch` to `maxPitch`. |
| `layout` | `"keyboard"` or `"even"` | `"keyboard"` | Like a piano, with the black keys between the white ones, or one equal share for each key, as the rows of a piano roll are. |
| `orientation` | `"horizontal"` or `"vertical"` | `"horizontal"` | Which way the keys run. A vertical keyboard puts the low end at the bottom. |
| `activeNotes` | `number[]` | | Pitches lit from elsewhere, such as a MIDI input or a sequencer, on top of the keys pressed here. |
| `disabled` | `boolean` | `false` | Plays nothing. |
| `onNoteOn` | `(pitch, details) => void` | | A key sounds. `details.cancel()` keeps it silent. |
| `onNoteOff` | `(pitch, details) => void` | | A key is released, the pointer glides off it, or it loses focus while held. |

## What a note reports

- `onNoteOn` gets `velocity` from 0 to 1, a `reason` (`"press"`, `"glide"` or `"keyboard"`), a `source` and the `event`.
- `onNoteOff` gets a `reason`: `"press"`, `"glide"` or `"keyboard"`.
- On the custom element, they are the `noteon` and `noteoff` events, with `detail: { value, reason, source, velocity }`, where `value` is the pitch.

## States to style from

- `data-active` on a key while it sounds, pressed here or listed in `activeNotes`.
- `data-color` on a key, `"black"` or `"white"`, `data-disabled`, `data-layout` and `data-orientation`.
