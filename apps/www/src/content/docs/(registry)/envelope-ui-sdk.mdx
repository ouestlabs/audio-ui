The envelope's behavior is one description, `envelope` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. It edits breakpoints, such as an ADSR shape or an automation curve: points to drag, add and remove, and segments to bend. Each framework renders it with a thin adapter that you copy into your project and own. The gestures, the keys, the grid and the limits on the number of points are the same in all four, and one suite of tests runs against each adapter.

The primitives are built on the [UI SDK](https://ui-sdk.dev) kernel, in beta. `@audio-ui/primitives` is not published yet: this page describes what the next release installs. The [knob](/docs/knob-ui-sdk), the [fader](/docs/fader-ui-sdk), the [XY pad](/docs/xypad-ui-sdk) and the [meter](/docs/meter-ui-sdk) are built the same way.

## Usage

A Root owns the points. A Graph is the surface they are edited on: it takes the double click that adds a point, and the Alt drag that bends a segment. A Line and a Fill draw the curve and the area under it, each as an `<svg>` stretched over the Graph. A Point is a handle for one point and a Segment a handle on the middle of the stretch between two.

You write a Point for each point and a Segment for each stretch, with their `index`: the Root's content can read its state, whose `value` is the points, so the handles follow the points as they are added and removed. That is a function in React, the default slot in Vue and a snippet in Svelte.

**Give the Graph its size and a position.** The pointer is read against the Graph's box, so a Graph with no height cannot take a click. Make it `position: relative` or `absolute`, and the Line and the Fill, which are absolute, take its box.

```tsx
import { useState } from "react";
import { Envelope } from "@/components/audio-ui/envelope/react";

export function Amp() {
  const [points, setPoints] = useState([
    { x: 0, y: 0 },
    { x: 0.15, y: 1 },
    { x: 0.6, y: 0.5 },
    { x: 1, y: 0 },
  ]);
  return (
    <Envelope.Root className="relative h-40 w-80" onValueChange={setPoints} value={points}>
      {({ value }) => (
        <>
          <Envelope.Graph className="absolute inset-0 rounded-md bg-muted">
            <Envelope.Fill className="text-primary/20" />
            <Envelope.Line className="text-primary" />
          </Envelope.Graph>
          {value.map((_, index) => (
            <Envelope.Point
              aria-label={`Point ${index + 1}`}
              className="size-3 rounded-full bg-primary"
              index={index}
              key={index}
            />
          ))}
          {value.slice(0, -1).map((_, index) => (
            <Envelope.Segment
              aria-label={`Curve ${index + 1}`}
              className="size-2 rounded-full bg-muted-foreground"
              index={index}
              key={index}
            />
          ))}
        </>
      )}
    </Envelope.Root>
  );
}
```

## Interaction

**Points**

- A drag moves a point, between its neighbors on `x`. With Shift it moves a quarter of the pointer's distance, for fine work, and the grid is ignored.
- Arrows move it by `step`, and Shift with an arrow by ten steps.
- A double click on the Graph adds a point where it is, snapped to the grid, which Cmd or Ctrl leaves.
- A double click on a point, Alt with a press, or Delete removes it. Removal is refused at `minPoints`, and adding at `maxPoints`.
- One point is the tab stop: Page Up and Page Down move to the next and the previous, Home and End to the first and the last.

**Segments**

- A drag on a segment's handle bends it, so the middle of the curve follows the pointer. With Alt, a drag anywhere on the Graph bends the segment under it.
- Up and Down bend it from the keyboard, Left and Right move to the next handle.
- A double click, Delete, or Alt with a double click on the Graph straightens it.
- A stretch between two points at the same level has nothing to bend: its handle carries `data-flat`.

A disabled envelope takes none of these.

## Options

Set on the Root, as props (an attribute in kebab case on the custom element, the points as JSON).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `{ x, y, curve? }[]` | an ADSR-like shape | The controlled points, or the starting ones. Each is normalized to 0 to 1 on both axes, sorted by `x`, and `curve`, from -1 to 1, bends the stretch that leaves it. |
| `minPoints`, `maxPoints` | `number` | `2`, none | How few and how many points there may be. Equal, the shape is fixed. |
| `snap` | `number` or `{ x, y }` | `0` | The grid the pointer snaps points to, in normalized units: `0.25` snaps to quarters, `0` is no grid, `{ x: 0.125, y: 0 }` snaps across and leaves the level free. |
| `step` | `number` | `0.01` | The keyboard step on both axes. |
| `format`, `locale` | `Intl.NumberFormat` options, a locale | | How a point's coordinates are written for its `aria-valuetext`. |
| `disabled` | `boolean` | `false` | Takes no gesture. |
| `onValueChange` | `(points, details) => void` | | Every change, which `details.cancel()` refuses. |
| `onValueCommitted` | `(points, details) => void` | | The end of a gesture. |

The Line takes a `strokeWidth`, in pixels, which stays the same however the Graph is stretched. A Point takes `getAriaValueText(point, index)` to announce itself in your own words, and a Segment `getAriaValueText(curve, index)`.

## What a change reports

`details` carries what moved the points and how:

- `reason`: `"drag"`, `"keyboard"`, `"add"`, `"remove"` or `"curve"` (a bend).
- `index`: the point or the segment that moved, or the index of the point that was added or removed.
- `source`: `"mouse"`, `"touch"`, `"pen"`, `"keyboard"` or `"programmatic"`, for analytics. It is never a reason to behave differently.
- `event`: the DOM event behind it, when there is one.
- `cancel()`: refuses the change. A controlled envelope keeps the points you give it.

While a pointer drags, the points follow it even if a controlled `value` lags behind.

On the custom element, `onValueChange` is an `input` event and `onValueCommitted` a `change` event, both with `detail: { value, reason, index, source }`, and `event.preventDefault()` refuses a change.

## States to style from

- `data-disabled` and `data-dragging` on every part.
- `data-blocked` on the Graph, briefly, when an addition was refused, and on a Point when its removal was refused: a feedback to animate. It is raised a frame after the change, so that an animation can play again.
- `data-removable` on a Point while there are more than `minPoints`, and `data-index` on a Point and a Segment.
- `data-flat` and `data-curve` on a Segment.

## Accessibility

A Point is a `role="slider"` on its level, from 0 to 1, and its `aria-valuetext` reads its coordinates, `0.5, 1`, with the format and the locale of the Root. A Segment is a slider on its curve, from -1 to 1. Give each an `aria-label`: the Graph, the Line and the Fill are hidden from assistive technology.

## Differences from the React envelope of `@audio-ui/react`

The behavior and the gestures are the same. These differ:

- The Graph is a `<div>` and not an `<svg>`. The Line and the Fill are each an `<svg>` over it, drawn in their `color`, where the React ones are polylines inside the Graph's svg.
- There are no `Points` and `Segments` parts: you write a Point and a Segment for each, and the Root's content reads `value` from its state. In React, the content is a function and must be the Root's only child.
- On custom elements the Points and the Segments are made for you, and take the name "Point 1" and "Curve 1".
- The Graph does not set its own position or size.
- Every part carries a `data-slot` attribute, such as `envelope-point`.
- A change reports a `source`.
