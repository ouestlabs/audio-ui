The sequencer's behavior is one description, `sequencer` in `@audio-ui/primitives`, over the controller of `@audio-ui/core`. It is a grid of steps to switch on and off, one row for each sound, as in a drum machine, with a velocity bar under each step. It holds two values, the pattern and the velocities. Each framework renders it with a thin adapter that you copy into your project and own, and one suite of tests runs against each adapter.

The primitives are built on the [UI SDK](https://ui-sdk.dev) kernel, in beta. `@audio-ui/primitives` is not published yet: this page describes what the next release installs. The [knob](/docs/knob-ui-sdk), the [fader](/docs/fader-ui-sdk), the [XY pad](/docs/xypad-ui-sdk), the [meter](/docs/meter-ui-sdk) and the [envelope](/docs/envelope-ui-sdk) are built the same way.

## Usage

A Root groups the rows. A Row is one sound, a Cell one of its steps, a `<button>` pressed when the step is on, and a Velocity a bar under a step. You write a Row for each row and a Cell for each step, with their `row` and `step`: the Root's content can read the state, `{ rows, steps }`, so the grid follows the pattern. That is a function in React, the default slot in Vue and a snippet in Svelte.

```tsx
import { Sequencer } from "@/components/audio-ui/sequencer/react";

const KIT = ["Kick", "Snare", "Hat"];

export function Beat({ pattern, onChange }: { pattern: boolean[][]; onChange: (pattern: boolean[][]) => void }) {
  return (
    <Sequencer.Root onValueChange={onChange} value={pattern}>
      {({ rows, steps }) =>
        Array.from({ length: rows }, (_, row) => (
          <Sequencer.Row aria-label={KIT[row]} className="flex gap-1" index={row} key={row}>
            {Array.from({ length: steps }, (_, step) => (
              <Sequencer.Cell
                aria-label={`${KIT[row]}, step ${step + 1}`}
                className="size-8 rounded bg-muted data-on:bg-primary data-current:ring-2"
                key={step}
                row={row}
                step={step}
              />
            ))}
          </Sequencer.Row>
        ))
      }
    </Sequencer.Root>
  );
}
```

On a custom element the sequencer makes the rows, the cells and the velocity bars itself, one for each step of its pattern. Add the `velocity-bars` attribute to get the bars.

**Velocity bars.** Write a Velocity for each step, in the Row, under the cells. Its height is the `--sequencer-velocity` CSS variable, from 0 to 1, which you read in your styles. It holds a native `<input type="range">` that carries its name and takes the keys.

## The step being played

Give the Root a `source`, a live value of the step being played, in the shape of an external store: `getSnapshot()` returns the step and `subscribe(listener)` is called on each tick. The step's cells get `data-current` straight in the DOM, so a clock ticking every step renders nothing. `createSource` from `@audio-ui/core` makes one, and `useTransportClock` from the registry gives you one on the audio clock.

On a custom element, `source` is a property, not an attribute.

## Interaction

**Cells**

- A press flips the step, and dragging on carries the new state across every cell the pointer crosses.
- Space and Enter flip the focused step. The cells are one tab stop: the arrows move by a step and by a row, Home and End go to the ends of a row.

**Velocity bars**

- A press sets the velocity where the pointer is, and dragging on draws across the steps of the row. Alt with a press brings it back to full.
- On the input, the arrows change it by 0.05, Page Up and Page Down by 0.25, Home and End go to silent and full, Delete and Backspace bring it back to full.

A disabled sequencer takes none of these.

## Options

Set on the Root, as props (an attribute in kebab case on the custom element, the grids as JSON).

| Option | Type | Default | |
| --- | --- | --- | --- |
| `value`, `defaultValue` | `boolean[][]` | | The pattern: a row for each sound, each a list of steps. Controlled, or the starting one. |
| `velocities`, `defaultVelocities` | `number[][]` | | How loud each step plays, from 0 to 1, a row for each sound like the pattern. A step it does not list plays at full. |
| `source` | `{ getSnapshot, subscribe }` | | The step being played, followed with no render. |
| `disabled` | `boolean` | `false` | Takes no gesture. |
| `onValueChange` | `(pattern, details) => void` | | A step is flipped. `details.cancel()` keeps the pattern as it was. |
| `onValueCommitted` | `(pattern, details) => void` | | A press, a paint or a key that changed the pattern ends. |
| `onVelocityChange` | `(velocities, details) => void` | | A velocity is drawn or nudged. |
| `onVelocityCommitted` | `(velocities, details) => void` | | A drag, a key or a reset that changed a velocity ends. |

## What a change reports

- Pattern: `reason` is `"press"`, `"paint"` or `"keyboard"`.
- Velocities: `reason` is `"drag"`, `"keyboard"`, `"input-change"` or `"reset"`.
- Both carry a `source` (`"mouse"`, `"touch"`, `"pen"`, `"keyboard"`) and the `event`.
- On the custom element, the pattern is the `input` and `change` events, and the velocities the `velocitychange` and `velocitycommit` events, with `detail: { value, reason, source }`.

## States to style from

- `data-on` and `aria-pressed` on a cell while its step is on, `data-current` while it is the step being played, `data-row` and `data-step` for its place.
- `data-painting` on the Root and the cells while a pointer paints.
- `data-disabled` on every part.

## Differences from the React sequencer of `@audio-ui/react`

The behavior and the `data-*` state attributes are the same. These differ:

- There are no `Rows` and `Cells` parts: you write a Row and a Cell for each, and the Root's content reads `rows` and `steps` from its state. In React, the content is a function and must be the Root's only child.
- A Cell and a Velocity take their `row` and `step` as props, where the React ones read the row from the Row they are in.
- On custom elements the rows, cells and bars are made for you.
- Every part carries a `data-slot` attribute, such as `sequencer-cell`.
- A change reports a `source`.
